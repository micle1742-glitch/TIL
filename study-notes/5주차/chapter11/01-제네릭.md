# 01-제네릭

---

## 1. 제네릭이란?

클래스나 메소드에서 사용할 자료형을 미리 고정하지 않고,
**사용하는 시점에 결정**하는 문법.

- 타입별 중복 코드를 줄임
- 잘못된 타입이 들어오는 걸 컴파일 시점에 방지

### 제네릭 없을 때 문제점

```java
NormalBox box = new NormalBox(); // Object 타입으로 저장
box.setContent(123);
String wrong = (String) box.getContent(); // 런타임에 ClassCastException 발생
```

> 컴파일 오류 없이 실행 시점에 터짐 → 찾기 어려운 버그

---

## 2. 제네릭 클래스 선언

```java
public class GenericBox<T> {  // T: 타입 매개변수
    private T content;

    public void setContent(T content) { this.content = content; }
    public T getContent() { return content; }
}
```

> T는 관례적인 이름. 반드시 T일 필요 없음
> 자주 쓰는 타입 매개변수 이름:
> - T: Type
> - E: Element (컬렉션)
> - K: Key
> - V: Value

---

## 3. 제네릭 클래스 사용

```java
GenericBox<String> stringBox = new GenericBox<>();
stringBox.setContent("안녕");
// stringBox.setContent(123); // 컴파일 에러 — String만 가능

String content = stringBox.getContent(); // 형변환 불필요
```

---

## 4. 기본 자료형은 Wrapper로

제네릭 타입 인자에는 **참조 자료형**만 사용 가능.

```java
GenericBox<Integer> intBox = new GenericBox<>(); // int → Integer
intBox.setContent(123);   // 오토박싱: int → Integer 자동
int result = intBox.getContent(); // 오토언박싱: Integer → int 자동
```

---

## 전체 흐름 정리

    제네릭 없음 (Object 사용)
    └─ 어떤 타입이든 저장 가능 → 타입 안전성 없음
    └─ 꺼낼 때 형변환 필요 → 런타임 ClassCastException 위험

    제네릭 사용
    └─ 사용 시점에 타입 결정: GenericBox<String>
    └─ 잘못된 타입 → 컴파일 에러로 바로 잡힘
    └─ 꺼낼 때 형변환 불필요

    자주 헷갈리는 것
    └─ 제네릭에 기본 자료형 불가 → int 대신 Integer, double 대신 Double
    └─ <> 안에 타입 지정 안 하면 Object와 같아져서 제네릭 의미 없음
    └─ T는 관례적 이름, 실제 타입이 아님

# 02-제네릭-타입제한

---

## 1. 타입 제한 (extends)

제네릭에서 특정 타입과 그 자식 타입만 허용하도록 제한.

```java
public class RabbitFarm<T extends Rabbit> {
    private T animal;
    ...
}
```

```java
RabbitFarm<Rabbit> farm1 = new RabbitFarm<>(new Rabbit());   // 허용
RabbitFarm<Bunny> farm2 = new RabbitFarm<>(new Bunny());     // 허용 (Rabbit 자식)
RabbitFarm<DrunkenBunny> farm3 = new RabbitFarm<>(new DrunkenBunny()); // 허용 (Bunny 자식)
// RabbitFarm<snake> farm4 = new RabbitFarm<>(new snake()); // 컴파일 에러 — Rabbit 자식 아님
```

> `<T extends Rabbit>` → Rabbit 또는 Rabbit의 자식 타입만 가능
> 타입 제한 없으면 어떤 타입이든 들어올 수 있어 위험

---

## 2. 클래스 구조

```
Animal (인터페이스)
├── Mammal implements Animal
│   └── Rabbit extends Mammal
│       └── Bunny extends Rabbit
│           └── DrunkenBunny extends Bunny
└── Raptile implements Animal
    └── snake extends Raptile  ← Rabbit 계열 아님 → RabbitFarm 사용 불가
```

---

## 3. 오버라이딩 + super 조합

```java
// Bunny
@Override
public void cry() {
    super.cry();  // 부모(Rabbit) cry() 먼저 실행
    System.out.println("바니바니 당근당근");
}

// DrunkenBunny
@Override
public void cry() {
    System.out.println("봐니봐니 당~!@#!@#근"); // 부모 것 버리고 완전히 재정의
}
```

---

## 전체 흐름 정리

    제네릭 타입 제한
    └─ <T extends 타입>: 해당 타입과 자식만 허용
    └─ 잘못된 타입은 컴파일 에러로 차단

    클래스 계층
    └─ Animal(인터페이스) → Mammal → Rabbit → Bunny → DrunkenBunny
    └─ snake는 Raptile 계열 → RabbitFarm<snake> 불가

    자주 헷갈리는 것
    └─ extends는 상속(클래스)과 제네릭 타입 제한 두 곳에서 사용
    └─ super.cry() 있으면 부모 것 먼저 실행 후 추가
    └─ super.cry() 없으면 부모 것 완전히 대체
