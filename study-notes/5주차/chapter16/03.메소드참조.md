# 03-메소드참조

---

## 1. 메소드 참조란?

람다가 새로운 동작을 만들지 않고 **이미 존재하는 메소드 하나를 그대로 호출할 때**,
그 호출을 `::`로 간결하게 표현하는 문법.

```java
value -> Integer.parseInt(value)   // 람다
Integer::parseInt                  // 메소드 참조 (같은 뜻)
```

---

## 2. 4가지 종류

### ① 클래스 :: static 메소드

```java
Function<String, Integer> parseInt = value -> Integer.parseInt(value);
Function<String, Integer> parseIntReference = Integer::parseInt;
parseIntReference.apply("123");   // 123
```

### ② 객체 :: 인스턴스 메소드

```java
Consumer<String> printer = message -> System.out.println(message);
Consumer<String> printerReference = System.out::println;
printerReference.accept("헬로 메소드 참조 !!");
```

> System.out이라는 이미 있는 객체의 println 사용

### ③ 클래스 :: 인스턴스 메소드 (첫 번째 입력이 주인공)

```java
BiPredicate<String, String> sameText = (left, right) -> left.equals(right);
BiPredicate<String, String> sameTextReference = String::equals;
sameTextReference.test("hello", "hello");   // true
```

> 입력 2개 중 첫 번째가 메소드를 호출하고, 두 번째가 매개변수로 들어감

### ④ 클래스 :: new (생성자 참조)

```java
Supplier<Account> newAccount = Account::new;                         // () -> new Account()
Function<String, Account> newAccountWithName = Account::new;         // name -> new Account(name)
BiFunction<String, Integer, Account> newAccountFull = Account::new;  // (name, balance) -> new Account(name, balance)
```

> 똑같은 `Account::new`인데 담는 인터페이스 모양(입력 개수)에 따라 **다른 생성자**가 호출됨
> Account에 생성자 오버로딩이 3개 있기 때문

---

## 3. 정리표

| 모양 | 람다로 풀면 |
|---|---|
| `클래스::static메소드` | `x -> 클래스.메소드(x)` |
| `객체::메소드` | `x -> 객체.메소드(x)` |
| `클래스::인스턴스메소드` | `(a, b) -> a.메소드(b)` |
| `클래스::new` | `x -> new 클래스(x)` |

### 못 줄이는 경우

```java
s -> s.trim().toUpperCase()   // 메소드 2개 이어 호출 → 불가
s -> "이름: " + s              // 메소드 호출이 아님 → 불가
```

## 전체 흐름 정리

    메소드 참조
    └─ 람다가 "받은 걸 그대로 메소드에 넘기기만" 할 때 :: 로 축약
    └─ static / 객체 / 클래스의 인스턴스 메소드 / 생성자 4종류
    └─ 생성자 참조는 인터페이스 모양에 따라 맞는 생성자 선택

    자주 헷갈리는 것
    └─ -> 는 람다, :: 는 메소드 참조
    └─ 메소드 이름 뒤에 괄호 안 씀 (println O, println() X)
    └─ 스트림에서 .forEach(System.out::println) 형태로 가장 많이 씀
