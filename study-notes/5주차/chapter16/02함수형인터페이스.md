# 02-함수형인터페이스

---

## 1. 자주 사용하는 함수형 인터페이스

매번 Calculator처럼 직접 만들지 않도록 Java가 `java.util.function`에 미리 만들어둔 것.

| 인터페이스 | 입력 | 출력 | 메소드 | 비유 |
|---|---|---|---|---|
| `Consumer<T>` | O | ❌ | `accept(t)` | 소비만 (출력) |
| `Supplier<T>` | ❌ | O | `get()` | 자판기 |
| `Function<T, R>` | O | O (다른 타입 가능) | `apply(t)` | 변환기 |
| `Predicate<T>` | O | boolean | `test(t)` | 검사기 (OX) |
| `UnaryOperator<T>` | O | O (**같은 타입**) | `apply(t)` | Function<T, T> |
| `BiPredicate<T, U>` | 2개 | boolean | `test(t, u)` | 입력 2개 검사기 |
| `BiFunction<T, U, R>` | 2개 | O | `apply(t, u)` | 입력 2개 변환기 |

> T = 입력 타입, R = 결과(Return) 타입, Bi = 입력 2개

---

## 2. 입력 처리 흐름 예제

```java
String input = "    java     ";

// Predicate: 검사 — null 아니고 공백만 있는 것도 아니면 true
Predicate<String> hasText = value -> value != null && !value.trim().isEmpty();
System.out.println(hasText.test(input));   // true

// UnaryOperator: 같은 타입으로 다듬기 — 앞뒤 공백 제거 + 대문자
UnaryOperator<String> normalize = value -> value.trim().toUpperCase();
String normalized = normalize.apply(input);   // "JAVA"

// Consumer: 출력만
Consumer<String> printer = value -> System.out.println("처리 결과 " + value);
printer.accept(normalized);   // 처리 결과 JAVA

// Function: 다른 타입으로 변환 — String → Integer
Function<String, Integer> length = value -> value.length();
System.out.println(length.apply(normalized));   // 4

// Supplier: 입력 없이 기본값 제공
Supplier<String> defaultValue = () -> "GUEST";
String blankInput = "  ";
String result = hasText.test(blankInput) ? normalize.apply(blankInput) : defaultValue.get();
printer.accept(result);   // 처리 결과 GUEST
```

### 포인트

- `value != null && ...` : `&&`는 앞이 false면 뒤를 안 봐서 null일 때 NPE 예방
- `조건 ? A : B` : 삼항연산자, true면 A / false면 B
- 실무: 입력값이 비었으면 기본값("GUEST") 처리하는 패턴

---

## 전체 흐름 정리

    입력 → Predicate(검사) → UnaryOperator(다듬기) → Function(변환) → Consumer(출력)
                          └ 실패 시 Supplier(기본값)

    외우는 법
    └─ 입력만: Consumer / 출력만: Supplier
    └─ 둘 다: Function / 둘 다인데 출력이 boolean: Predicate
    └─ 입출력 같은 타입: UnaryOperator / 입력 2개: Bi~
