# 01-예외처리

---

## 1. 예외처리란?

프로그램 실행 중 발생한 문제를 감지하고 **안내 / 기록 / 복구** 방법을 정하는 것.

```java
int number = Integer.parseInt("abc"); // NumberFormatException → 프로그램 종료
```

### 에러 메시지 읽는 법

```
Exception in thread "main" java.lang.NumberFormatException: For input string: "abc"
    at ...Integer.parseInt(Integer.java:662)
    at ...Application.main(Application.java:5)
```

> 첫 줄: 어떤 예외 + 원인
> at 줄들(스택 트레이스): 예외가 지나온 호출 경로
> **내가 짠 파일이 처음 나오는 줄** = 고칠 위치

---

## 2. throw — 예외 직접 발생

```java
public void checkEnoughMoney(int price, int money) throws Exception {
    System.out.println("가지고 계신 돈은" + money + "원 입니다.");

    if (money >= price) {
        System.out.println("상품을 구입하기 위한 돈이 충분합니다");
    } else {
        throw new Exception("돈이 부족합니다!!"); // 여기서 실행 흐름 끝
    }

    System.out.println("즐거운 쇼핑 하세요~"); // 예외 발생 시 실행 안 됨
}
```

> throw 실행되면 **그 아래 코드는 실행 안 되고** 메소드를 바로 빠져나감

---

## 3. throws — 예외를 호출한 쪽에 넘김

메소드 선언부에 붙여서 "이 메소드는 예외를 던질 수 있으니 호출한 쪽이 처리해"라고 알림.

```java
public static void main(String[] args) throws Exception {
    ExceptionTest et = new ExceptionTest();
    et.checkEnoughMoney(10000, 50000); // 정상
    et.checkEnoughMoney(50000, 10000); // 예외 발생
    System.out.println("프로그램을 종료합니다."); // 실행 안 됨
}
```

### 실행 결과

```
가지고 계신 돈은50000원 입니다.
상품을 구입하기 위한 돈이 충분합니다
즐거운 쇼핑 하세요~
가지고 계신 돈은10000원 입니다.
Exception in thread "main" java.lang.Exception: 돈이 부족합니다!!
```

> main도 throws로 넘기면 위에 JVM밖에 없음 → **아무도 처리 안 함 → 프로그램 종료**
> 그래서 "프로그램을 종료합니다."도 출력 안 됨

---

## 4. throw vs throws

| | throw | throws |
|---|---|---|
| 의미 | 예외를 **지금 발생**시킴 | 예외가 **나갈 수 있다고 선언** |
| 위치 | 메소드 안 | 메소드 선언부 `()` 뒤 |
| 예시 | `throw new Exception("...")` | `void method() throws Exception` |

---

## 5. 왜 돈이 충분해도 빨간 줄이 뜨나?

```java
et.checkEnoughMoney(10000, 50000); // 돈 충분한데도 처리 안 하면 컴파일 에러
```

> 컴파일러는 값을 계산하지 않고 **선언부의 throws만 보고 판단**
> → "이 메소드 예외 던질 수 있음, 너 대비했냐?" 무조건 처리 요구
> 해결: try-catch로 잡거나, throws로 또 넘기거나

| | Checked 예외 | Unchecked 예외 |
|---|---|---|
| 예시 | `Exception`, `IOException` | `NumberFormatException`, `NullPointerException` |
| 처리 안 하면 | 컴파일 에러 (빨간 줄) | 컴파일은 통과 |

---

## 전체 흐름 정리

    예외 발생
    └─ throw new Exception("메시지") → 그 아래 코드 실행 X

    처리 방법 두 가지
    └─ try-catch: 여기서 직접 처리
    └─ throws: 호출한 쪽에 넘김

    main까지 throws로 넘기면
    └─ JVM이 받음 → 아무도 처리 안 함 → 프로그램 종료

    자주 헷갈리는 것
    └─ throw(던지는 행동) vs throws(던질 수 있다는 경고문)
    └─ 빨간 줄 사라짐 ≠ 처리됨 (throws는 넘긴 것뿐)
    └─ 컴파일 에러는 값과 상관없이 선언부 기준
    └─ 실무: 아래 계층은 throws, 처리 방법 아는 위에서 try-catch

## 1. 슈퍼클래스와 서브클래스

- **슈퍼클래스(SuperClass)**: 부모 클래스
- **서브클래스(SubClass)**: 부모 클래스를 상속받는 자식 클래스
- `extends`: 클래스를 상속할 때 사용

```java
public class SuperClass {
    public void method() throws IOException {}
}

public class SubClass extends SuperClass {
}
```

> 부모 메소드를 자식 클래스에서 오버라이딩할 때는 예외 선언 규칙을 지켜야 함.

---

## 2. 오버라이딩 시 예외 처리 규칙

슈퍼클래스의 메소드:

```java
public void method() throws IOException {}
```

서브클래스에서 오버라이딩할 때는 부모가 선언한 Checked 예외의 범위를 벗어날 수 없음.

### ① 예외를 선언하지 않는 경우 — 허용

```java
@Override
public void method() {}
```

부모가 예외를 선언했더라도 자식은 예외를 선언하지 않을 수 있음.

### ② 부모와 같은 예외 — 허용

```java
@Override
public void method() throws IOException {}
```

부모와 같은 예외를 선언할 수 있음.

### ③ 더 구체적인 예외 — 허용

```java
@Override
public void method() throws FileNotFoundException {}
```

`FileNotFoundException`은 `IOException`의 하위 클래스이므로 허용됨.

### ④ 더 넓은 범위의 예외 — 허용되지 않음

```java
@Override
public void method() throws Exception {}
```

`Exception`은 `IOException`보다 범위가 넓으므로 허용되지 않음.

---

## 3. 예외 선언 규칙 비교

| 서브클래스의 예외 선언 | 허용 여부 |
|---|---|
| 예외 선언 없음 | O |
| `throws IOException` | O |
| `throws FileNotFoundException` | O |
| `throws Exception` | X |

---

## 4. 핵심 문법 정리

- `extends`: 부모 클래스를 상속함.
- `@Override`: 부모 메소드를 재정의한다는 것을 표시함.
- `throws`: 메소드에서 발생할 수 있는 예외를 선언함.
- Checked 예외: 오버라이딩할 때 부모가 선언한 예외보다 넓은 범위로 선언할 수 없음.

---

## 전체 흐름 정리

    슈퍼클래스
    └─ method() throws IOException
         ↓
    서브클래스에서 오버라이딩
    ├─ 예외 선언 안 함 → 허용
    ├─ 같은 예외 선언 → 허용
    ├─ 더 구체적인 예외 선언 → 허용
    └─ 더 넓은 예외 선언 → 허용되지 않음

**핵심 암기**

- 자식 메소드는 부모보다 더 넓은 Checked 예외를 선언할 수 없음.
- `FileNotFoundException`은 `IOException`의 하위 클래스임.
- 예외를 선언하지 않는 것은 가능하지만, 부모보다 더 넓은 Checked 예외를 선언하는 것은 불가능함.
