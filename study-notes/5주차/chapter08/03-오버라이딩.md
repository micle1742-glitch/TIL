# section03. 오버라이딩 (Overriding)

---

## 1. 오버라이딩이란?

부모에게 물려받은 메소드를 자식의 목적에 맞게 같은 형태로 다시 작성하는 것.

```java
// VendingMachine.java (부모)
public String vend() { return "밀크 커피"; }

// CoffeeVendingMachine.java (자식)
@Override
public String vend() { return "아이스아메리카노"; }
```

---

## 2. 오버라이딩 성공 조건

| 조건 | 설명 |
|------|------|
| 메소드 이름 | 부모와 동일 |
| 매개변수 목록 | 부모와 동일 |
| 반환 타입 | 부모와 동일 (또는 자식 타입) |
| 접근제한자 | 부모와 같거나 더 넓어야 함 |

> 접근제한자 범위: private < default < protected < public
> 부모가 protected면 자식은 protected 또는 public만 가능

---

## 3. 오버라이딩 불가 대상

```java
// 1. private 메소드 — 자식에게 보이지 않음
private void checkStock() { ... }

// 2. final 메소드 — 변경 금지, 호출은 가능
public final void powerOn() { ... }

// 3. 생성자 — 상속되지 않음
```

> final 메소드: 모든 자식이 같은 규칙을 반드시 따라야 한다는 의도를 표현

---

## 4. 오버로딩과 헷갈리지 않기

```java
// 오버라이딩 — 매개변수 동일, 부모 메소드 재정의
@Override
public String vend() { return "아이스아메리카노"; }

// 오버로딩 — 매개변수 다름, 새로운 메소드 추가 (오버라이딩 아님)
public String vend(String type) { return type; }
```

> 매개변수가 다르면 오버라이딩이 아니라 오버로딩

---

## 5. toString() — System.out.println(객체)

```java
System.out.println(coffeeVendingMachine);
// 출력: com.ohgiraffers.section03.overriding.CoffeeVendingMachine@주소값
```

- 객체를 println에 넘기면 자동으로 `toString()` 호출
- 기본값은 `클래스명@해시코드`
- `toString()`을 오버라이딩하면 원하는 형식으로 출력 가능

```java
@Override
public String toString() {
    return "CoffeeVendingMachine 객체";
}
```

## 전체 흐름 정리

    VendingMachine (부모)
    └─ vend() → "밀크 커피"
    └─ private checkStock() → 오버라이딩 불가
    └─ final powerOn() → 오버라이딩 불가, 호출은 가능
    └─ protected clean() → 오버라이딩 가능

    CoffeeVendingMachine extends VendingMachine (자식)
    └─ vend() 오버라이딩 → "아이스아메리카노"
    └─ clean() 오버라이딩 → 스팀 청소
    └─ vend(String type) 추가 → 오버로딩 (별개 메소드)

    자주 헷갈리는 것
    └─ 매개변수 같으면 오버라이딩, 다르면 오버로딩
    └─ private/final은 오버라이딩 불가
    └─ 접근제한자는 부모보다 좁게 못 씀 (더 넓게는 가능)
    └─ println(객체) → toString() 자동 호출
