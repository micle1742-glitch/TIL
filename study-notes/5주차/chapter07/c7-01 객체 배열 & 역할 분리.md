## 1. 객체 배열

기본 자료형 배열과 구조가 같고, 칸마다 객체의 참조값이 들어간다.
배열 자체도 heap, 실제 객체도 heap에 따로 존재한다.

### 선언 방식

    // 방법 1: 선언 → 생성 → 초기화
    Car[] carArray = new Car[3];    // 방 3칸, 각 칸은 null
    System.out.println(carArray[0]); // null — 아직 객체 안 넣었으므로
    carArray[0] = new Car("페라리", 300);

    // 방법 2: 선언과 동시에 초기화
    Car[] carArray2 = {
        new Car("페라리", 300),
        new Car("람보르기니", 350)
    };

### 순회

    // 인덱스 필요하거나 요소 교체할 때
    for (int i = 0; i < carArray.length; i++) {
        carArray[i].driveMaxSpeed();
    }

    // 읽기만 할 때 (인덱스 접근 불가, 요소 교체 불가)
    for (Car car : carArray2) {
        car.driveMaxSpeed();
    }

### 최댓값 찾기

    Car fastestCar = carArray[0];   // 첫 요소를 기준값으로

    for (int i = 1; i < carArray.length; i++) {
        if (carArray[i].getMaxSpeed() > fastestCar.getMaxSpeed()) {
            fastestCar = carArray[i];
        }
    }

> 숫자 최댓값 패턴과 동일 — 비교 기준만 getter로 꺼내는 차이

## 2. 역할 분리 — Application / Service / Repository

한 클래스에 입력·처리·저장을 몰아넣지 않고 역할대로 분리한다.
Spring의 Controller → Service → Repository 계층 구조의 기초 형태.

| 클래스 | 역할 |
|--------|------|
| Application | 사용자 입력, 메뉴 흐름 제어 |
| MemberService | 기능 처리 (등록·조회·검색 로직) |
| MemberRepository | 데이터 저장·조회 (배열 보관) |
| Member | DTO — 데이터만 담는 클래스, 필드 + getter/setter만 존재 |

### MemberRepository 핵심 포인트

    private static final Member[] members;
    private static int count;

    static {
        members = new Member[10];   // 클래스 로드 시 1번만 실행, 생성자보다 먼저
    }

    public static boolean store(Member[] newMembers) {
        if (count + newMembers.length > members.length) return false;
        for (int i = 0; i < newMembers.length; i++) {
            members[count++] = newMembers[i];  // 현재 위치에 저장 후 count 증가
        }
        return true;
    }

> `members[count++]` — 후위 증가: 현재 count 위치에 저장한 뒤 count를 1 올림

### MemberService 핵심 포인트

    // 전체 조회 — null 체크 필수 (빈 칸 있을 수 있음)
    for (Member m : MemberRepository.findAllMembers()) {
        if (m != null) System.out.println(m.getInformation());
    }

    // 검색 — 플래그 변수 패턴 (찾았는지 여부 추적)
    boolean isFound = false;
    for (Member m : MemberRepository.findAllMembers()) {
        if (m != null && searchId.equals(m.getId())) {
            isFound = true;
            break;
        }
    }
    if (!isFound) System.out.println("해당 아이디 회원을 찾을 수 없습니다.");

### Application — Scanner 주의

    int no = sc.nextInt();   // 숫자만 읽고 엔터('\n')는 버퍼에 남김
    sc.nextLine();           // 남은 엔터 제거 — 이게 없으면 다음 nextLine()이 빈 값 읽음

## 전체 흐름 정리

    객체 배열
    └─ new Car[3] → 방만 생성, 각 칸 null
    └─ carArray[i] = new Car() 해야 실제 객체 들어감
    └─ for-each: 읽기 전용 / 인덱스 필요하거나 교체할 땐 일반 for
    └─ 최댓값: 첫 요소 기준잡고 getter로 비교

    역할 분리
    └─ Application → Service → Repository 순으로 호출
    └─ Member(DTO): 데이터 전달용, 로직 없음

    자주 헷갈리는 것
    └─ == vs .equals() : 주소 비교 vs 값 비교 (String은 반드시 equals)
    └─ nextInt() 후 nextLine() 소비 필수
    └─ 객체 배열 순회 시 null 체크 안 하면 NullPointerException
    └─ count++ : 저장 후 증가 (선 저장, 후 증가)
    └─ isFound 패턴: 탐색 성공 여부를 boolean으로 추적하는 플래그 변수 패턴
