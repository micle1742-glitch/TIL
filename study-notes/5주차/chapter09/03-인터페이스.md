# 03-인터페이스

---

## 1. 인터페이스란?

클래스가 반드시 구현해야 할 기능의 규칙(약속)을 정의하는 것.

```java
public interface IConnectable {
    void connect();    // 추상 메소드 — public abstract 생략 가능
    void disconnect();
}
```

> 인터페이스 안에는 일반 메소드 불가 (추상 메소드만)
> 인스턴스 필드 불가 (상수만 가능)
> 직접 객체 생성 불가

---

## 2. 구현 (implements)

```java
public class Keyboard implements IConnectable {
    @Override
    public void connect() { System.out.println("키보드 연결"); }

    @Override
    public void disconnect() { System.out.println("키보드 해제"); }
}
```

> implements로 구현
> 인터페이스의 모든 추상 메소드를 반드시 오버라이딩해야 함
> 여러 인터페이스 동시 구현 가능: `implements A, B, C`

---

## 3. 다형성 적용

인터페이스 타입으로 구현 객체 참조 가능.

```java
public void connectDevice(IConnectable device) { // 인터페이스 타입 매개변수
    device.connect(); // Keyboard든 Mouse든 모두 수용
}

computer.connectDevice(new Keyboard());
computer.connectDevice(new Mouse());
```

> 추상 클래스와 같은 원리 — 타입 하나로 여러 구현 객체 다룸

---

## 4. 추상 클래스 vs 인터페이스

| | 추상 클래스 | 인터페이스 |
|---|---|---|
| 선언 키워드 | `abstract class` | `interface` |
| 구현 키워드 | `extends` | `implements` |
| 객체 생성 | 불가 | 불가 |
| 인스턴스 필드 | ✅ 가능 | ❌ 불가 |
| 공통 상태 | ✅ 가능 | ❌ 불가 |
| 일반 메소드 | ✅ 가능 | ❌ 불가 |
| 상속/구현 수 | 하나만 | 여러 개 가능 |
| 목적 | 공통 속성·기능 물려주기 | 기능의 약속 강제 |

---

## 전체 흐름 정리

    IConnectable (인터페이스)
    └─ connect(), disconnect() 추상 메소드 정의

    Keyboard / Mouse implements IConnectable
    └─ 두 메소드 반드시 오버라이딩

    Computer
    └─ 매개변수를 IConnectable 타입으로 선언
    └─ Keyboard든 Mouse든 동일하게 처리 (다형성)

    자주 헷갈리는 것
    └─ 인터페이스는 interface, 구현은 implements
    └─ 추상 메소드에 public abstract 생략 가능 (자동 적용)
    └─ 인터페이스는 여러 개 동시 구현 가능
    └─ 인터페이스도 참조변수 타입으로 사용 가능 (다형성)
