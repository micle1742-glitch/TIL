# section01. 다형성 (Polymorphism)

---

## 1. 다형성이란?

부모 타입 하나로 여러 자식 객체를 다룰 수 있는 성질.
같은 메소드를 호출해도 실제 객체에 따라 다른 동작이 실행됨.

```java
Animal a1 = new Rabbit(); // 업캐스팅
Animal a2 = new Tiger();  // 업캐스팅

a1.cry(); // "토끼가 뀨~"
a2.cry(); // "호랑이가 어흥"
```

---

## 2. 업캐스팅 (Upcasting)

자식 객체를 부모 타입 변수에 저장하는 것. 자동으로 됨.

```java
Animal a1 = new Rabbit(); // 자동 형변환
```

> 부모 타입으로는 부모에 정의된 메소드만 접근 가능
> 자식 고유 메소드(jump, bite)는 접근 불가

---

## 3. 동적 바인딩

```
컴파일 시 → 부모 타입의 메소드를 호출하는 것으로 보임
실행(runtime) 시 → 실제 객체(Rabbit, Tiger)의 오버라이딩된 메소드가 실행됨
```

```java
Animal a1 = new Rabbit();
a1.cry(); // 컴파일: Animal의 cry() / 실행: Rabbit의 cry()
```

---

## 4. 다운캐스팅 (Downcasting)

자식 고유 메소드를 쓰려면 부모 타입을 자식 타입으로 명시적 형변환.

```java
// a1.jump();          // 에러 — 부모 타입으로 자식 고유 메소드 접근 불가
((Rabbit)a1).jump();   // 다운캐스팅 후 접근 가능
```

> 실제 객체가 Rabbit인데 Tiger로 다운캐스팅하면 ClassCastException 발생
> 반드시 instanceof로 확인 후 다운캐스팅

---

## 5. instanceof 연산자

다운캐스팅 전에 실제 객체 타입을 확인하는 안전장치.

```java
System.out.println(a1 instanceof Tiger);  // false

if (a1 instanceof Rabbit) {
    ((Rabbit)a1).jump(); // 안전하게 다운캐스팅
}
```

---

## 6. 매개변수에 다형성 적용

다형성 적용 전: 타입마다 메소드 따로 만들어야 함.

```java
public void feed(Rabbit rabbit) { rabbit.eat(); }
public void feed(Tiger tiger) { tiger.eat(); }
```

다형성 적용 후: 부모 타입 하나로 처리.

```java
public void feed(Animal animal) {
    animal.eat(); // 실제 객체에 따라 Rabbit/Tiger의 eat() 실행
}
```

> 새로운 동물 클래스가 추가돼도 feed() 메소드를 새로 만들 필요 없음

---

## 7. 다형성 + 객체 배열

```java
Animal[] animals = new Animal[5];
animals[0] = new Rabbit();
animals[1] = new Tiger();

for (Animal animal : animals) {
    animal.cry(); // 각 객체에 맞는 cry() 실행
}

for (Animal animal : animals) {
    if (animal instanceof Rabbit) {
        ((Rabbit)animal).jump();
    } else if (animal instanceof Tiger) {
        ((Tiger)animal).bite();
    }
}
```

---

## 전체 흐름 정리

    업캐스팅
    └─ Animal a = new Rabbit() — 자동, 부모 메소드만 접근 가능

    동적 바인딩
    └─ 컴파일: 부모 메소드로 보임
    └─ 실행: 실제 객체의 오버라이딩된 메소드 실행

    다운캐스팅
    └─ ((Rabbit)a).jump() — 자식 고유 메소드 접근
    └─ 반드시 instanceof 확인 후 사용

    다형성 활용
    └─ 매개변수를 부모 타입으로 선언 → 모든 자식 객체 수용
    └─ 배열을 부모 타입으로 선언 → 여러 자식 객체 한 번에 관리

    자주 헷갈리는 것
    └─ 업캐스팅은 자동, 다운캐스팅은 명시적으로 (타입)
    └─ 부모 타입으로는 자식 고유 메소드 호출 불가
    └─ 잘못된 다운캐스팅 → ClassCastException 발생
    └─ instanceof로 타입 확인 후 다운캐스팅하는 것이 안전
