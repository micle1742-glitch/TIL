# 정답

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | IoC(제어의 역전) | 내가 new로 만들던 객체의 제어권이 컨테이너로 넘어간다. |
| 2 | Bean | 컨테이너(ApplicationContext)가 Bean을 보관하고 꺼내준다. |
| 3 | 결합도 | 객체 생성이 코드에 박혀 있어 결합도가 높아진다. |
| 4 | ① GenericXmlApplicationContext | Java 설정 방식은 AnnotationConfigApplicationContext를 쓴다. |
| 5 | ② AnnotationConfigApplicationContext | `new AnnotationConfigApplicationContext(설정클래스.class)`로 생성한다. |
| 6 | 패키지 포함 전체 경로 | 클래스 이름만 쓰면 컨테이너가 클래스를 찾지 못한다. |
| 7 | ref | value는 문자열·숫자 같은 기본값, ref는 다른 Bean의 id이다. |
| 8 | @Configuration | @Configuration 클래스 안의 @Bean 메서드가 반환한 객체가 Bean이 된다. |
| 9 | getMember | @Bean에 name을 주지 않으면 메서드 이름이 Bean 이름이 된다. |
| 10 | @ComponentScan | `@ComponentScan(basePackages = "...")`로 스캔 범위를 지정한다. |
| 11 | memberDAO | @Component의 기본 Bean 이름은 클래스명의 첫 글자를 소문자로 바꾼 것이다. |
| 12 | DI(의존성 주입) | A가 B를 사용하면 A는 B에 의존한다고 한다. |
| 13 | ① constructor-arg | 세터 주입에는 `<property>`를 쓴다. |
| 14 | property | property 방식은 기본 생성자와 setter가 있어야 동작한다. |
| 15 | Service | Service는 비즈니스 로직을 담당하고 Controller는 Repository를 직접 부르지 않는다. |
| 16 | 구현체 교체가 쉬움(Service 코드 수정 불필요) | 메모리용인지 DB용인지 몰라도 되므로 구현체만 바꾸면 된다. |
| 17 | @Autowired | 이름이 아니라 타입 기준으로 찾는다. |
| 18 | 생성자 주입 | final을 쓸 수 있어 한 번 주입되면 바뀌지 않고 의존 객체 없이는 생성이 안 된다. |
| 19 | 생성자가 딱 1개일 때 | 스프링 4.3 이상에서 생성자가 1개뿐이면 생략 가능하다. |
| 20 | final | 생성자 주입은 final을 쓸 수 있어 권장되고, 필드 주입은 final 사용이 불가능하다. |
| 21 | ① NoUniqueBeanDefinitionException | 같은 타입 후보가 여러 개라 스프링이 하나를 고르지 못한다. |
| 22 | @Primary | @Primary는 구현체에 붙인다. |
| 23 | ② @Qualifier | `@Qualifier("pikachu")`처럼 대소문자를 정확히 써야 한다. |
| 24 | @Qualifier | 더 구체적인 지정이 우선한다. |
| 25 | Bean 이름 | List는 객체만, Map은 Bean 이름(key)과 객체(value)를 받는다. |
| 26 | singleton | 아무것도 지정하지 않으면 singleton이다. |
| 27 | prototype | 손님마다 장바구니가 따로 필요한 경우에 쓴다. |
| 28 | false | prototype은 getBean마다 새 객체를 만든다(singleton이면 true). |
| 29 | ② destroyMethod | 생성 후 실행은 initMethod이고, 값은 메서드 이름 문자열이다. |
| 30 | close() | close()를 하지 않으면 destroy 메서드가 실행되지 않는다. |
| 31 | ① @PropertySource | 경로는 resources 폴더 기준이다. |
| 32 | key가 없을 때 쓰는 기본값 | 콜론 뒤가 기본값이며, 기본값이 없는데 key가 없으면 에러가 난다. |
| 33 | ④ Pointcut | `execution(* 패키지.*Service.*(..))`처럼 대상을 지정한다. |
| 34 | @Around | 매개변수로 JoinPoint가 아닌 ProceedingJoinPoint를 받는다. |
| 35 | ③ @AfterThrowing | 정상 반환 후에만 실행되는 것은 @AfterReturning이다. |
| 36 | @SpringBootApplication | 이 클래스가 있는 패키지와 하위 패키지를 스캔한다. |
| 37 | @RestController | @Controller + @ResponseBody이며, Map·DTO를 반환하면 Jackson이 JSON으로 변환한다. |
| 38 | DELETE /api/v1/menus/{menuCode} | 메소드 주소는 클래스 주소 뒤에 이어 붙는다. |
| 39 | CREATED | ResponseEntity.ok()는 200 OK이다. |
| 40 | @RequestParam | required = false면 없을 때 null, defaultValue면 기본값이 들어간다. |
| 41 | ② @PathVariable | 경로의 `{menuCode}` 이름과 매개변수를 연결한다. |
| 42 | @RequestBody | JSON 키 이름과 DTO 프로퍼티 이름이 같아야 하고 기본 생성자가 필요하다. |
| 43 | 직렬화 | 반대로 JSON을 Java 객체로 바꾸는 것은 역직렬화이다. |
| 44 | @JsonProperty | `@JsonProperty("memberNo")`는 직렬화·역직렬화 모두에 적용된다. |
| 45 | ② @RestControllerAdvice | 메소드에는 @ExceptionHandler(예외.class)를 붙여 예외 타입별로 처리한다. |
| 46 | @Valid | 검증에 실패하면 MethodArgumentNotValidException이 발생한다. |
| 47 | 404 | 대상이 없는 것은 서버 오류(500)가 아니라 404 Not Found이다. |
