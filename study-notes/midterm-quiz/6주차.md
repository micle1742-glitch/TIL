# 정답

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | 1 | AND가 OR보다 먼저 계산되어 1 OR (0 AND 0) = 1 OR 0 = 1이다. |
| 2 | BETWEEN | `>= 10000 AND <= 25000`과 같다. |
| 3 | 이름이 '마늘'로 시작하는 메뉴 | `%`는 0글자 이상 아무거나를 뜻하고 `_`는 정확히 한 글자이다. |
| 4 | IS | NULL은 `= NULL`로 비교할 수 없고 `IS NULL`/`IS NOT NULL`을 써야 한다. |
| 5 | DISTINCT | 여러 열이면 지정한 열의 조합이 같을 때만 중복으로 본다. |
| 6 | 6번째부터 5개 | `LIMIT [건너뛸 개수], [가져올 개수]`이므로 앞 5개를 건너뛴다. |
| 7 | INNER JOIN | 짝이 없는 행은 결과에서 빠진다(교집합). |
| 8 | ② LEFT JOIN | FROM 쪽(왼쪽) 테이블이 기준이다. |
| 9 | SELF JOIN | 하위 카테고리와 상위 카테고리처럼 한 테이블 안의 행 사이 관계를 볼 때 쓴다. |
| 10 | ② HAVING | WHERE는 그룹화 전 개별 행에 쓰고 집계 함수를 쓸 수 없다. |
| 11 | WITH ROLLUP | 마지막 줄의 NULL 행이 전체 총계이다. |
| 12 | 상관 서브쿼리 | 예: `WHERE category_code = a.category_code`처럼 바깥 별칭을 참조한다. |
| 13 | 별칭 | 파생 테이블은 별칭이 없으면 에러가 난다. |
| 14 | ① UNION | 중복을 포함하는 것은 UNION ALL이다. |
| 15 | 차집합 | LEFT JOIN은 A를 모두 남기고 B에 없으면 NULL이 된다. |
| 16 | REPLACE | UPDATE가 아니라 삭제 후 다시 추가하는 방식이다. |
| 17 | 테이블 전체 행이 수정된다 | WHERE 조건이 없으면 모든 행이 대상이다. |
| 18 | 트랜잭션 | All or Nothing이며 성공하면 COMMIT, 실패하면 ROLLBACK한다. |
| 19 | 자동으로 COMMIT된다(암시적 커밋) | 그래서 이후 ROLLBACK으로 되돌릴 수 없다. |
| 20 | ② TRUNCATE | DROP은 테이블 자체를 삭제한다. |
| 21 | DELETE | DELETE는 DML이고 TRUNCATE와 DROP은 DDL이라 ROLLBACK이 안 된다. |
| 22 | CHANGE COLUMN | 이름이 그대로여도 기존 이름을 두 번 써야 한다. |
| 23 | PRIMARY KEY | NULL도 중복도 허용하지 않는다. |
| 24 | ② UNIQUE | PRIMARY KEY와 달리 NULL이 가능하다. |
| 25 | FOREIGN KEY | `REFERENCES 부모테이블(컬럼)`으로 지정한다. |
| 26 | NULL | CASCADE면 자식도 함께 삭제되고, 옵션이 없으면 삭제가 막힌다. |
| 27 | CHECK | 조건에 맞지 않는 값은 INSERT가 거부된다. |
| 28 | 3 | MySQL의 +는 문자열 이어붙이기가 아니라 숫자 덧셈이다(암시적 형변환). |
| 29 | SIGNED | `CAST(AVG(menu_price) AS SIGNED INTEGER)`처럼 쓴다. |
| 30 | 인덱스 | 없으면 테이블 전체를 훑는 Full Table Scan을 한다. |
| 31 | 탈 수 없다 | 앞에 %가 오면 인덱스를 못 타고 `'iph%'`처럼 뒤에 %가 와야 가능하다. |
| 32 | 쓰기(INSERT/UPDATE/DELETE) | 데이터 변경 때 인덱스도 함께 고쳐야 하고 저장 공간도 더 쓴다. |
| 33 | load | `load(Reader)`로 키=값 설정을 읽고 `getProperty("키")`로 꺼낸다. |
| 34 | SQL Injection | Statement는 취약하고 PreparedStatement는 안전하다. |
| 35 | ② PreparedStatement | Statement는 문자열 이어붙이기라 취약하고 실무에선 거의 안 쓴다. |
| 36 | ② executeUpdate() | SELECT는 `executeQuery()`로 ResultSet을 반환한다. |
| 37 | ② loadFromXML() | FileInputStream으로 읽고 `getProperty(키)`로 쿼리를 꺼낸다. |
| 38 | 오버로딩 | 매개변수 타입만 다르게 같은 이름의 메서드를 정의한다. |
| 39 | 9 | FROM 없이 SELECT만 써도 연산 결과를 확인할 수 있다. |
| 40 | DESC | ASC는 오름차순(기본값), DESC는 내림차순이다. |
| 41 | b.category_code | JOIN은 두 테이블의 공통 컬럼(category_code)이 같은 행끼리 연결한다. |
| 42 | GROUP BY | GROUP BY가 같은 값끼리 묶고 COUNT(*)가 그룹별 행 개수를 센다. |
