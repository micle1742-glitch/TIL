# 문제

**1.** [개념] 렌더링 사이에 계산 결과값을 기억하고, 의존성이 바뀔 때만 다시 계산하는 Hook은?

**2.** [개념] 의존성이 바뀌지 않으면 이전 함수의 참조(reference)를 재사용하게 해주는 Hook은?

**3.** [개념] 값이 바뀌어도 리렌더링을 일으키지 않고, DOM 요소에 접근할 때도 쓰는 Hook은?

**4.** [개념] 여러 컴포넌트에서 재사용할 수 있도록 Hook 로직을 함수로 분리한 것은?

**5.** [개념] 비동기 작업의 결과를 다음 콜백에서 처리하며 콜백이 계속 중첩되어 코드가 깊어지는 현상은?

**6.** [개념] 비동기 작업의 미래 결과(성공/실패)를 나타내는 객체는?

**7.** [개념] Promise 체인에서 실패나 오류를 처리하는 메서드는?

**8.** [개념] 성공·실패와 관계없이 마지막에 실행되며 로딩 종료 같은 공통 작업에 쓰는 메서드는?

**9.** [단답] `callAPI()`가 반환하는 것은?

```js
async function callAPI() {
    return '완료';
}
```

**10.** [개념] Promise가 처리될 때까지 현재 async 함수의 실행을 잠시 멈추고 결과를 받는 키워드는?

**11.** [단답] `fetch(url)`을 `await` 없이 호출하면 무엇이 반환되는가?

**12.** [단답] `const response = await fetch(url);`에서 `response`는 무엇인가?

**13.** [단답] `await response.json()`의 결과는 무엇인가?

**14.** [개념] fetch 응답이 성공 범위(200~299)인지 알려주며, 404/500을 직접 오류로 처리할 때 확인하는 값은?

**15.** [단답] Axios에서 서버 응답 데이터는 응답 객체의 어떤 프로퍼티로 접근하는가?

**16.** [개념] loading, error 상태에 따라 조건을 먼저 return해서 화면을 분기하는 패턴은?

**17.** [단답] 빈칸은? (콜백 방식의 위치 API를 await로 쓸 수 있게 감싼다)

```js
const getPosition = () => {
    return ______((resolve, reject) => {
        navigator.geolocation.getCurrentPosition(resolve, reject);
    });
};
```

**18.** [개념] Next.js App Router에서 여러 페이지에 공통으로 쓰이는 화면 구조를 만드는 파일은?

**19.** [단답] `app/menu/[menuCode]/page.js`에서 URL이 `/menu/5`일 때 `menuCode`의 값은?

**20.** [개념] 동적 라우팅에서 URL의 파라미터 값(예: menuCode)을 가져오는 Hook은?

**21.** [개념] JSX에서 사용자가 클릭해 페이지를 이동하게 하는 Next.js 컴포넌트는?

**22.** [개념] `router.push('/menu/search')`처럼 JavaScript 코드로 페이지를 이동시킬 때 쓰는 Hook은?

**23.** [단답] URL이 `/menu/search?menuName=열무`일 때 `searchParams.get('menuName')`의 결과는?

**24.** [개념] Query String(`?menuName=열무`)의 값을 가져올 때 쓰는 Hook은?

**25.** [개념] 현재 URL의 경로(예: `/menu`)를 가져와 네비게이션 활성 표시에 쓸 수 있는 Hook은?

**26.** [개념] App Router의 서버 컴포넌트 기본값 대신, 파일 맨 위에 써서 클라이언트 컴포넌트로 지정하는 문구는?

**27.** [개념] 부모의 데이터를 여러 단계의 자식 컴포넌트를 거쳐 props로 계속 전달해야 하는 문제 구조는?

**28.** [개념] Store를 만들어 여러 컴포넌트에서 전역 상태를 관리하게 해주는 라이브러리는?

**29.** [단답] Zustand Store를 만드는 함수 빈칸은?

```js
export const useStore = ______((set) => ({ count: 0 }));
```

**30.** [단답] CRUD에서 데이터의 일부를 수정(Update)할 때 쓰는 HTTP 메서드는?

**31.** [개념] Zustand 상태를 localStorage 등에 저장해 새로고침 후에도 유지하게 해주는 middleware는?

**32.** [개념] 서버가 처음 렌더링한 결과와 브라우저의 첫 렌더링 결과가 달라 생기는 문제는?

**33.** [개념] 서버 데이터를 가져오고 로딩·에러·캐시·재요청을 관리하는 라이브러리는?

**34.** [개념] `QueryClient`를 하위 컴포넌트에서 쓸 수 있도록 제공하는 컴포넌트는?

**35.** [개념] useQuery에서 어떤 Query인지 구분하는 키(예: `["users"]`)는?

**36.** [개념] useQuery에서 실제로 서버 데이터를 가져오는 함수를 지정하는 옵션은?

**37.** [개념] useQuery의 상태 중 처음 데이터를 불러오는 로딩을 처리할 때 주로 쓰는 값은?

**38.** [개념] useQuery에서 재요청까지 포함해 현재 fetch가 진행 중인지 알려주는 값은?

# 정답

| 번호 | 정답 | 해설 |
|---|---|---|
| 1 | useMemo | useMemo는 함수가 아니라 계산된 값을 기억한다. |
| 2 | useCallback | useCallback은 함수 참조, useMemo는 계산 결과값을 기억한다. |
| 3 | useRef | ref.current를 바꿔도 그 자체로 리렌더링이 발생하지 않는다. |
| 4 | Custom Hook | 예: useDelayReady(delay)처럼 Hook 로직을 함수로 분리해 여러 컴포넌트에서 재사용한다. |
| 5 | 콜백 지옥(Callback Hell) | 가독성과 유지보수성이 떨어져 Promise나 async/await를 쓴다. |
| 6 | Promise | pending, fulfilled, rejected 세 가지 상태를 가진다. |
| 7 | .catch() | .then()은 성공 결과를 처리한다. |
| 8 | .finally() | try/catch/finally의 finally와 같은 역할이다. |
| 9 | Promise | async 함수는 문자열을 반환해도 항상 Promise를 반환한다. |
| 10 | await | 브라우저 전체가 멈추는 것은 아니다. |
| 11 | Promise | 서버 데이터가 바로 들어오는 것이 아니라 Promise 객체가 반환된다. |
| 12 | Response 객체 | 아직 파싱된 JSON 데이터가 아니다. |
| 13 | 파싱된 JavaScript 데이터(객체·배열) | response.json()도 Promise를 반환하므로 await가 필요하다. |
| 14 | response.ok | fetch는 HTTP 404/500만으로는 자동 reject되지 않는다. |
| 15 | response.data | Fetch는 response.json()이 필요하지만 Axios는 JSON을 자동 파싱해 data로 제공한다. |
| 16 | Early Return | 보통 error → loading → 데이터 순서로 검사한다. |
| 17 | new Promise | new Promise로 감싸면 `await getPosition()`처럼 쓸 수 있다. |
| 18 | layout.js | `children` 자리에 현재 page.js 내용이 들어온다. |
| 19 | 5 | `[menuCode]`는 URL의 동적인 부분이다. |
| 20 | useParams() | Query String은 useSearchParams로 가져온다. |
| 21 | Link | 코드로 이동시키는 것은 useRouter이다. |
| 22 | useRouter() | Link는 링크를 눌러 이동, useRouter는 코드로 이동한다. |
| 23 | "열무" | `?키=값`의 Query String에서 값을 가져온다. |
| 24 | useSearchParams() | 동적 라우팅 값은 useParams, Query String은 useSearchParams이다. |
| 25 | usePathname() | `pathname === path`로 현재 페이지를 비교할 수 있다. |
| 26 | 'use client' | useRouter, useParams 등을 쓰는 페이지에 필요하다. |
| 27 | Props Drilling | 이를 줄이기 위해 Zustand 같은 전역 상태 관리를 쓴다. |
| 28 | Zustand | `create()`로 Store를 만들고 `set()`으로 상태를 바꾼다. |
| 29 | create | `import { create } from "zustand"`로 가져온다. |
| 30 | PATCH | Create=POST, Read=GET, Update=PATCH, Delete=DELETE. |
| 31 | persist | `name`은 localStorage에 저장할 키 이름이다. |
| 32 | Hydration 문제 | isMounted 상태로 마운트 이후에 화면을 그리는 방식으로 해결한다. |
| 33 | React Query(TanStack Query) | 내부 상태는 Zustand, 서버 데이터는 React Query가 담당한다. |
| 34 | QueryClientProvider | useQuery를 쓰기 전에 Provider 설정이 필요하다. |
| 35 | queryKey | queryFn은 데이터를 어떻게 가져올지 정하는 함수이다. |
| 36 | queryFn | queryKey는 식별, queryFn은 가져오는 방법이다. |
| 37 | isLoading | 재요청까지 포함해 fetch 중인지 확인하는 것은 isFetching이다. |
| 38 | isFetching | isLoading은 처음 로딩, isFetching은 재요청 포함 진행 여부이다. |
