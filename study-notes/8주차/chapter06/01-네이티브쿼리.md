# chap06 - Native Query 복습

## 0. 오늘의 큰 그림
- JPQL로 안 되는 SQL(윈도우 함수, DB 전용 문법)은 **SQL을 직접** 쓴다
- 결과가 엔티티가 아니면 **인터페이스(View)** 로 받는다
- 흐름: `nativeQuery = true` SQL → 각 행을 View 인터페이스로 → getter → JSON

---

## 1) @Query + nativeQuery = true

    @Query(value = """
        SELECT c.category_code AS categoryCode,
               c.category_name AS categoryName,
               COUNT(m.menu_code) AS menuCount
          FROM tbl_category c
          LEFT JOIN tbl_menu m ON m.category_code = c.category_code
         GROUP BY c.category_code, c.category_name
         ORDER BY menuCount DESC, c.category_code
        """, nativeQuery = true)
    List<CategoryMenuCountView> findCategoryMenuCounts();

- JPQL과 달리 **테이블명·컬럼명**(tbl_menu, menu_code)을 씀
- `AS 별칭`이 View의 getter 이름과 맞아야 값이 들어감

## 2) @NativeQuery (같은 뜻, 더 짧게)

    @NativeQuery(value = """
        SELECT m.menu_code AS menuCode, m.menu_name AS menuName, m.menu_price AS menuPrice,
               RANK() OVER (ORDER BY m.menu_price DESC) AS priceRank
          FROM tbl_menu m
         ORDER BY priceRank, m.menu_code
        """)
    List<MenuPriceRankView> findMenuPriceRanks();

- `RANK() OVER (...)` 같은 윈도우 함수는 JPQL에 없어서 Native로

## 3) 결과 받는 View 인터페이스

    public interface CategoryMenuCountView {
        int getCategoryCode();
        String getCategoryName();
        long getMenuCount();
    }

- 구현 클래스 안 만들어도 Spring Data JPA가 객체를 만들어 줌
- Jackson이 getter로 JSON 변환 → `[{ "categoryCode":1, "categoryName":"...", "menuCount":3 }]`

---

## 헷갈리는 부분
| | JPQL | Native Query |
|---|---|---|
| 쓰는 이름 | 엔티티·필드명 (Menu, menuCode) | 테이블·컬럼명 (tbl_menu, menu_code) |
| DB 바뀌면 | 그대로 | SQL 수정 필요할 수 있음 |
| 결과 | 엔티티 | 보통 View 인터페이스 |
- COUNT는 `long`으로 받기
