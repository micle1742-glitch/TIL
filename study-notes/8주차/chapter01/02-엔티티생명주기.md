# chap01 - 엔티티 생명주기 복습 (section03)

## 0. 오늘의 큰 그림
- 같은 Menu 객체라도 **영속성 컨텍스트가 관리하는지**에 따라 상태가 다름
- 상태에 따라 변경 감지, 1차 캐시가 동작하는지가 달라짐
- 확인 방법: `entityManager.contains(menu)` → 관리 중이면 true

| 상태 | 뜻 | 들어가는 방법 | 변경 감지 |
|---|---|---|---|
| 비영속 (new/transient) | 만들었지만 JPA가 모르는 객체 | `new Menu(...)` | X |
| 영속 (managed) | 영속성 컨텍스트가 관리 중 | `persist()`, `find()`, `merge()`의 반환값 | O |
| 준영속 (detached) | 관리되다가 분리됨 | `detach()`, `clear()`, `close()` | X |
| 삭제 (removed) | 삭제 대상으로 지정 | `remove()` | flush 때 DELETE |

---

## 1) 비영속 vs 영속

    Menu managedMenu = entityManager.find(Menu.class, 2);              // 영속
    Menu transientMenu = new Menu(managedMenu.getMenuCode(), ...);     // 값은 같지만 비영속

    assertTrue(entityManager.contains(managedMenu));
    assertFalse(entityManager.contains(transientMenu));

- PK와 값이 똑같아도 `new`로 만든 객체는 관리 대상이 아님

---

## 2) 같은 / 다른 EntityManager에서 조회

    // 같은 EntityManager
    Menu menu1 = entityManager.find(Menu.class, 3);
    Menu menu2 = entityManager.find(Menu.class, 3);
    assertSame(menu1, menu2);           // 1차 캐시 → 같은 객체

    // 다른 EntityManager
    Menu menu1 = entityManager.find(Menu.class, 3);
    Menu menu2 = otherEntityManager.find(Menu.class, 3);
    assertNotSame(menu1, menu2);        // 영속성 컨텍스트가 다름 → 다른 객체

- 동일성 보장은 **같은 영속성 컨텍스트 안에서만**

---

## 3) detach - 준영속이면 변경 감지 X

    Menu foundMenu = entityManager.find(Menu.class, 10);
    entityManager.detach(foundMenu);                    // 준영속
    foundMenu.setMenuPrice(originalPrice + 1000);
    entityManager.flush();                              // UPDATE 안 나감

    Menu reloadedMenu = entityManager.find(Menu.class, 10);
    assertEquals(originalPrice, reloadedMenu.getMenuPrice());   // 가격 그대로
    assertFalse(entityManager.contains(foundMenu));

---

## 4) merge - 준영속 → 새 영속 객체를 반환

    Menu detachedMenu = entityManager.find(Menu.class, 10);
    entityManager.detach(detachedMenu);
    detachedMenu.setMenuName("병합된 메뉴 이름");

    Menu mergedMenu = entityManager.merge(detachedMenu);
    entityManager.flush();                                    // UPDATE

    assertFalse(entityManager.contains(detachedMenu));        // 넘긴 객체는 여전히 준영속
    assertTrue(entityManager.contains(mergedMenu));           // 반환된 객체가 영속
    assertNotSame(detachedMenu, mergedMenu);

- merge는 넘긴 객체를 다시 관리하는 게 아니라, 관리되는 객체에 **값을 복사**해서 그 객체를 반환
- 그래서 merge 뒤에는 **반환값**을 써야 함

---

## 5) clear / remove

    // clear: 전부 준영속 → 다시 find하면 새 객체 (SELECT 다시)
    Menu firstMenu = entityManager.find(Menu.class, 6);
    entityManager.clear();
    Menu secondMenu = entityManager.find(Menu.class, 6);
    assertFalse(entityManager.contains(firstMenu));
    assertNotSame(firstMenu, secondMenu);

    // remove: 삭제 상태 → flush 때 DELETE
    entityManager.remove(foundMenu);
    entityManager.flush();
    entityManager.clear();
    assertNull(entityManager.find(Menu.class, 6));

| | detach(entity) | clear() | close() |
|---|---|---|---|
| 대상 | 객체 하나 | 컨텍스트의 전부 | 전부 + EntityManager 종료 |

---

## 헷갈리는 부분
- **준영속 vs 비영속**: 둘 다 관리 안 됨. 준영속은 한 번 관리됐었고 PK(식별자)가 있음, 비영속은 처음부터 관리된 적 없음
- **merge의 반환값**: `merge(a)` 후에도 `a`는 준영속. 영속 객체는 반환값 `b` (a != b)
- **remove는 즉시 DELETE가 아님**: 삭제 상태로 표시 → flush/commit 때 DELETE
- **detach 후 값을 바꿔도** 에러는 없음, 그냥 DB에 반영이 안 될 뿐
- `contains()` = 이 EntityManager가 관리 중인지 (DB에 있는지가 아님)

---

## 암기할 것
- 비영속(new) → 영속(persist/find) → 준영속(detach/clear/close) / 삭제(remove)
- 변경 감지는 **영속 상태**에서만
- merge는 새 영속 객체를 **반환** (넘긴 객체는 준영속 그대로)
- 같은 영속성 컨텍스트 + 같은 PK → 같은 객체 (assertSame)

---

## 전체 흐름 정리
- new로 만든 객체는 비영속, persist/find로 영속성 컨텍스트에 들어가면 영속
- 영속 상태일 때만 1차 캐시, 변경 감지가 동작
- detach/clear/close로 분리되면 준영속 → 값을 바꿔도 UPDATE 없음
- 준영속을 다시 반영하려면 merge → 반환된 영속 객체 사용
- remove로 삭제 상태가 되면 flush 때 DELETE
