# chap02 - 엔티티 매핑과 @Embedded 복습

## 0. 오늘의 큰 그림

- chap02: **Spring Boot + Spring Data JPA** 시작 → 설정은 application.yml, EntityManager는 Spring이 주입, 트랜잭션은 @Transactional
- section01: 엔티티 필드 ↔ 테이블 컬럼 매핑 (`@Column`, `@Enumerated`)

## 1) application.yml

    spring:
      datasource:
        url: jdbc:mysql://localhost:3306/menudb
        ...
      jpa:
        show-sql: true
        hibernate:
          ddl-auto: create      # 시작할 때 엔티티 기준으로 테이블을 지우고 새로 만듦
        properties:
          hibernate:
            format_sql: true

| ddl-auto | 동작 |
|---|---|
| create | 시작 시 DROP 후 CREATE (기존 데이터 사라짐) |
| create-drop | create + 종료 시 DROP |
| update | 바뀐 부분만 반영 |
| validate | 엔티티와 테이블이 맞는지 검사만 |
| none | 아무것도 안 함 (chap03부터 사용) |

## 2) 엔티티 매핑 - Member

    @Entity
    @Table(name = "tbl_member")
    public class Member {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)    // DB auto_increment
        @Column(name = "member_no")
        private int memberNo;

        @Column(name = "member_id", nullable = false, unique = true, length = 50)
        private String memberId;

        @Column(name = "enroll_date", nullable = false)
        private LocalDateTime enrollDate;

        @Enumerated(EnumType.STRING)                           // enum을 이름으로 저장
        @Column(name = "member_role", nullable = false)
        private MemberRole memberRole;                         // ROLE_MEMBER, ROLE_ADMIN

        protected Member() {}                                  // JPA용 기본 생성자
        public Member(String memberId, ...) { ... }            // 새 회원용 생성자
    }

| 어노테이션 | 역할 |
|---|---|
| `@Entity` | JPA가 관리할 클래스 |
| `@Table(name)` | 연결할 테이블 |
| `@Id` | 기본 키 필드 |
| `@GeneratedValue(IDENTITY)` | PK를 DB가 생성 (INSERT할 때) |
| `@Column(name, nullable, unique, length)` | 컬럼 이름 / NOT NULL / UNIQUE / 길이 |
| `@Enumerated(EnumType.STRING)` | enum을 문자열로 저장 |

- nullable, unique, length는 ddl-auto로 **테이블을 만들 때** 제약조건으로 들어감
- `LocalDateTime` 같은 날짜 타입은 그대로 매핑됨

## 3) Repository / Service (Spring 방식)

    @Repository
    public class MemberRepository {
        @PersistenceContext
        private EntityManager entityManager;      // Spring이 주입

        public Member save(Member member) {
            entityManager.persist(member);
            return member;
        }
    }

    @Service
    public class MemberRegistService {
        @Transactional
        public Member registMember(MemberRegistDTO newMember) {
            Member member = new Member(newMember.getMemberId(), ...);   // DTO → 엔티티
            return memberRepository.save(member);
        }
    }

- `@PersistenceContext`: 현재 트랜잭션에 맞는 EntityManager를 주입
- begin/commit 코드 대신 `@Transactional` → 메소드 끝나면 커밋 (예외면 롤백)
- IDENTITY라 persist 순간 INSERT → 반환된 member에 memberNo가 채워짐

## 4) @Embeddable / @Embedded - 값 객체

    @Embeddable                                   // 다른 엔티티 안에 들어갈 값 객체
    public class Price {
        @Column(name = "regular_price", nullable = false)
        private int regularPrice;
        @Column(name = "dicount_rate", nullable = false)
        private double discountRate;
        @Column(name = "sell_price", nullable = false)
        private int sellPrice;

        protected Price() {}
        public Price(int regularPrice, double discountRate) {
            validatePrice(regularPrice);              // 음수면 IllegalArgumentException
            validateDiscountRate(discountRate);       // 0~1 밖이면 IllegalArgumentException
            this.sellPrice = calculateSellPrice(regularPrice, discountRate);
        }
    }

    @Entity
    @Table(name = "tbl_book")
    public class Book {
        @Embedded
        private Price price;          // Price의 필드 3개가 tbl_book의 컬럼이 됨
    }

    // 테스트: 43000원, 할인율 0.1 → 판매가 38700
    assertEquals(38700, savedBook.getPrice().getSellPrice());
    assertThrows(IllegalArgumentException.class, () -> new Price(43000, 1.1));

- **별도 테이블이 아님** → tbl_book 안에 regular_price, dicount_rate, sell_price 컬럼
- 가격 관련 값과 규칙(검증, 판매가 계산)을 Price 한 곳에 모음 → Book이 단순해짐
- Price는 @Id가 없음 (엔티티가 아님)

## 5) 테스트 - @SpringBootTest + @Transactional (+ @Commit)

    @SpringBootTest
    @Transactional
    public class MemberRegistServiceTests {
        @Test
        @Commit                       // 이 테스트는 롤백하지 않고 커밋
        void testRegistMember() { ... }
    }

- 테스트의 @Transactional은 기본이 **롤백** → `@Commit`을 붙이면 DB에 남음 (테이블에서 확인용)

## 헷갈리는 부분
- **EnumType.STRING vs ORDINAL**: 기본값은 ORDINAL(순서 번호 0, 1). enum 순서를 바꾸거나 중간에 추가하면 DB 값의 의미가 바뀜 → STRING 사용
- **기본 생성자가 protected인 이유**: JPA는 조회 결과로 객체를 만들 때 기본 생성자가 필요. public이면 아무 데서나 빈 객체를 만들 수 있으니 protected로 막음
- **@Embeddable vs @Embedded**: 값 객체 클래스에 @Embeddable, 그걸 쓰는 엔티티 필드에 @Embedded
- **ddl-auto: create 주의**: 실행할 때마다 테이블을 지우고 새로 만듦 → 실제 데이터 있는 DB에 쓰면 안 됨
- **@PersistenceContext vs 생성자 주입**: EntityManager는 @PersistenceContext로 주입 (트랜잭션마다 맞는 EntityManager로 연결해 주는 프록시가 들어옴)
- `nullable = false`는 테이블 생성 시 NOT NULL 제약조건 → ddl-auto: none이면 이미 있는 테이블 구조가 기준

---

## 암기할 것
- @Entity, @Table(name), @Id, @GeneratedValue(strategy = GenerationType.IDENTITY), @Column(name, nullable, unique, length)
- @Enumerated(EnumType.STRING)
- @Embeddable(값 객체) + @Embedded(엔티티 필드) → 같은 테이블 컬럼
- ddl-auto: create / create-drop / update / validate / none
- @PersistenceContext EntityManager, @Transactional, 테스트 @Commit

---

## 전체 흐름 정리
- Spring Boot가 application.yml로 DataSource와 JPA를 설정
- 엔티티 필드는 @Column으로 컬럼과 매핑, enum은 STRING으로 저장
- 값 객체는 @Embeddable로 만들고 엔티티에 @Embedded로 포함 → 같은 테이블에 저장
- Service의 @Transactional 안에서 DTO로 엔티티를 만들고 Repository가 persist
- 테스트는 기본 롤백, 확인하고 싶으면 @Commit
