# 오늘 배운 내용 정리

## 1. React 컴포넌트
- React에서 화면을 구성하는 하나의 단위
- JavaScript 함수로 컴포넌트를 만들 수 있음
- 컴포넌트를 여러 개로 나누면 코드 관리와 재사용이 쉬워짐

## 2. 컴포넌트 조합
- 작은 컴포넌트를 다른 컴포넌트 안에서 사용해서 하나의 화면을 구성
- 핵심: **컴포넌트로 나누기 → 필요한 곳에서 조합하기**

## 3. Props
- 부모 컴포넌트가 자식 컴포넌트에게 데이터를 전달하는 방법
- 함수의 매개변수와 비슷한 개념
- 자식은 전달받은 Props를 읽어서 사용
- Props 자체를 직접 변경하지 않음

### 기억하기
- Props = **외부에서 전달받는 값**

## 4. State
- 컴포넌트가 내부에서 관리하는 데이터
- State가 변경되면 React가 화면을 다시 렌더링함
- State를 변경할 때는 setter 함수를 사용

### 기억하기
- State = **내가 관리하는 값**

## 5. Hook
- 함수형 컴포넌트에서 React의 기능을 사용할 수 있게 해주는 함수
- 대표적인 Hook이 `useState`

## 6. useState
- State를 만들고 관리하는 Hook

예:
    const [message, setMessage] = useState('안녕하세요');

`useState()`는 개념적으로 배열 형태의 값을 반환함.

    [현재 State 값, State를 변경하는 함수]

그래서 배열 구조 분해 할당으로:

    const [message, setMessage] = useState('안녕하세요');

처럼 사용하는 것.

개념적으로 생각하면:

    const state = useState('안녕하세요');

    state[0] → 현재 값
    state[1] → 값을 변경하는 함수

즉,

    message → 현재 State 값
    setMessage → State 변경 함수

## 7. Setter
- State를 변경하는 함수
- `setMessage()`, `setNumber()` 등이 setter
- setter로 State가 변경되면 React가 다시 렌더링함

### 흐름
    setter 호출
        ↓
    State 변경
        ↓
    컴포넌트 다시 실행
        ↓
    새로운 JSX 계산
        ↓
    화면 업데이트

## 8. Rerender
- State가 변경되었을 때 컴포넌트 함수가 다시 실행되는 과정
- 변경된 State를 기준으로 JSX가 다시 계산되고 필요한 화면 부분이 업데이트됨

### 쉽게 생각하기
    처음 실행 → 화면 생성

    State 변경
        ↓
    컴포넌트 함수 다시 실행
        ↓
    새로운 값으로 JSX 다시 계산
        ↓
    화면 업데이트

## 9. 함수형 컴포넌트와 함수형 업데이트는 다름

### 함수형 컴포넌트
    function App() {
        return <h1>Hello</h1>;
    }

- JavaScript 함수로 만든 React 컴포넌트

### 함수형 업데이트
    setNumber(prev => prev + 1);

- 이전 State 값을 받아서 새로운 State를 계산하는 방식

## 10. ReactDOM.createRoot
    const root = ReactDOM.createRoot(
        document.getElementById('root')
    );

- HTML의 `#root` 영역을 React가 관리할 수 있도록 연결

    root.render(<App />);

- React의 `App` 컴포넌트를 `#root`에 화면으로 표시

## 11. React 이벤트

HTML/JS에서는:
    addEventListener()

React에서는 JSX에서:
    onClick
    onChange
    onSubmit

등을 사용함.

예:
    <button onClick={handleEnter}>입력</button>

여기서 `handleEnter`는 함수를 **전달**하는 것.

❌
    onClick={handleEnter()}

→ 렌더링할 때 바로 실행됨

⭕
    onClick={handleEnter}

→ 클릭했을 때 실행됨

## 12. 화살표 함수로 이벤트 처리

    <button onClick={() => setNumber(number + 1)}>
        증가
    </button>

화살표 함수 자체를 `onClick`에 전달하고,
버튼을 클릭하면 그 안의 `setNumber()`가 실행됨.

## 13. Input의 value와 placeholder

    value
    → 현재 실제 입력값

    placeholder
    → 사용자가 입력하기 전에 보여주는 안내 문구

예:
    <input
        placeholder="아이디를 입력하세요"
        value={username}
    />

`placeholder`는 실제 입력값이 아니고,
실제 값은 `value`로 관리함.

## 14. onChange
- Input의 값이 변경될 때 실행되는 이벤트

    onChange={e => setUsername(e.target.value)}

순서:

    사용자가 입력
        ↓
    onChange 실행
        ↓
    e.target
        ↓
    현재 입력창
        ↓
    e.target.value
        ↓
    현재 입력값
        ↓
    setUsername()
        ↓
    State 변경

### 핵심 기억
- `onChange` = **입력값 저장**
- `value` = **저장된 값 보여주기**

## 15. Controlled Input

React에서는 Input의 값을 State와 연결할 수 있음.

    const [username, setUsername] = useState('');

    <input
        value={username}
        onChange={e => setUsername(e.target.value)}
    />

전체 흐름:

    사용자 입력
        ↓
    onChange
        ↓
    e.target.value
        ↓
    setUsername()
        ↓
    username State 변경
        ↓
    rerender
        ↓
    value={username}
        ↓
    Input에 현재 State 표시

즉,

    Input → State
    onChange + e.target.value + setter

    State → Input
    value={state}

## 16. Input State를 따로 관리하는 방법

    const [username, setUsername] = useState('');
    const [email, setEmail] = useState('');

각각의 Input마다 State와 setter를 하나씩 만드는 방식.

예:
    <input
        value={username}
        onChange={e => setUsername(e.target.value)}
    />

    <input
        value={email}
        onChange={e => setEmail(e.target.value)}
    />

## 17. 여러 Input을 하나의 객체 State로 관리

    const [form, setForm] = useState({
        username: '',
        email: ''
    });

여러 입력값을 하나의 객체로 관리할 수도 있음.

    const { username, email } = form;

객체 구조 분해 할당으로 값을 꺼낼 수 있음.

## 18. 여러 Input을 하나의 handleChange로 관리

    const handleChange = (e) => {
        const { name, value } = e.target;

        setForm({
            ...form,
            [name]: value
        });
    };

Input:

    <input
        name="username"
        value={form.username}
        onChange={handleChange}
    />

    <input
        name="email"
        value={form.email}
        onChange={handleChange}
    />

## 19. ...form
    ...form

- 기존 객체의 값을 복사하는 역할

예:

    form = {
        username: '영동',
        email: 'test@test.com'
    }

    {
        ...form,
        email: 'new@test.com'
    }

결과:

    {
        username: '영동',
        email: 'new@test.com'
    }

기존 `username`은 유지하고 `email`만 변경할 수 있음.

## 20. [name]: value
    [name]: value

이것은 계산된 속성명.

예를 들어:

    name = 'username'
    value = '영동'

이면 실제로:

    username: '영동'

이 됨.

또:

    name = 'email'
    value = 'test@test.com'

이면:

    email: 'test@test.com'

이 됨.

그래서 Input마다 별도의 `handleChange`를 만들 필요 없이 `name`을 이용해서 하나의 함수로 처리할 수 있음.

## 21. 오늘 배운 React 핵심 흐름

    컴포넌트
      ↓
    State 생성
      ↓
    Input과 State 연결
      ↓
    onChange 발생
      ↓
    e.target.value로 입력값 가져오기
      ↓
    setter로 State 변경
      ↓
    React rerender
      ↓
    value에 State가 다시 표시됨

## 22. 오늘 가장 중요한 것

    Props = 부모 → 자식으로 전달받는 값

    State = 컴포넌트가 관리하는 값

    useState = State를 만들고 관리하는 Hook

    setter = State를 변경하는 함수

    onChange = Input이 변경될 때 실행

    e.target = 이벤트가 발생한 요소

    e.target.value = 그 Input의 현재 값

    value = State 값을 Input에 보여줌

    rerender = State 변경 후 컴포넌트가 다시 실행되어 화면을 업데이트하는 과정
