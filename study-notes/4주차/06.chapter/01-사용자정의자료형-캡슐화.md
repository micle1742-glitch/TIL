## section01. 사용자 정의 자료형

### 1. 클래스란?

객체가 어떤 데이터(속성)와 기능(메소드)을 가져야 하는지 정의하는 설계도.
실제 객체를 만들기 위한 정의서일 뿐, 클래스 자체가 객체는 아님.

```java
public class Member {
    String id;
    String pwd;
    String name;
    int age;
    char gender;
    String[] hobby;
}
```

### 2. 객체 생성 및 사용

```java
// 자료형 변수명 = new 클래스명();
Member member = new Member();

// . (참조 연산자)로 필드 접근
member.id = "user01";
member.age = 5;
member.hobby = new String[]{"볼링", "배드민턴"};

System.out.println(member.id);
```

> 개별 변수(int age, String name...)로 관리하면 변수가 늘어날수록 관리가 힘듦
> 클래스로 묶으면 관련 데이터를 하나의 객체로 관리 가능

### 3. 필드(Field)란?

클래스 내부에 선언하여 객체가 관리하는 데이터를 나타내는 변수.
지역 변수와 다르게 객체가 살아있는 동안 유지됨.

## section02. 캡슐화 (Encapsulation)

### 1. 캡슐화란?

필드를 `private`으로 감추고, 메소드를 통해서만 접근하게 하는 방식.
외부에서 잘못된 값이 들어오는 걸 막기 위해 사용.

```java
// 캡슐화 전 — 외부에서 마음대로 수정 가능
member.age = -10; // 음수도 들어감

// 캡슐화 후 — setter에서 검증
child1.setAge(-10); // 내부에서 막아줌
```

### 2. 접근제한자

| 기호 | 종류 | 범위 |
|------|------|------|
| + | public | 모든 패키지에서 접근 가능 |
| # | protected | 같은 패키지 + 상속받은 자식 |
| ~ | default | 같은 패키지 안에서만 (아무것도 안 쓴 것) |
| - | private | 해당 클래스 내부에서만 |

> 최상위 클래스에는 public 또는 default만 사용 가능
> 필드는 보통 private, 메소드는 보통 public

### 3. Getter / Setter

```java
private int age;

// Setter — 외부에서 값 설정, 검증 가능
public void setAge(int age) {
    if (age >= 0) {
        this.age = age;
    } else {
        System.out.println("나이는 음수일 수 없습니다.");
        this.age = 0;
    }
}

// Getter — 내부 값을 외부에 반환
public int getAge() {
    return this.age;
}
```

> this.age: 현재 객체의 필드 (매개변수 age와 구분)
> getter만 만들고 setter 없으면 읽기 전용
> IntelliJ 자동 생성: Alt + Insert → Getter and Setter

## 전체 흐름 정리

    클래스
    └─ 설계도 — 객체가 가질 데이터(필드)와 기능(메소드) 정의
    └─ new 로 실제 객체 생성
    └─ . (참조 연산자)로 필드·메소드 접근

    캡슐화
    └─ 필드를 private으로 감춤
    └─ setter: 외부 값 받아 검증 후 필드에 저장
    └─ getter: 필드 값을 외부에 반환
    └─ 잘못된 값(음수 나이 등) 들어오는 것을 메소드에서 막을 수 있음

    자주 헷갈리는 것
    └─ 클래스 = 설계도, 객체 = 실제로 만든 것 (new)
    └─ 필드 = 클래스 안에 선언된 변수 (객체마다 별도 존재)
    └─ this.필드 = 현재 객체의 필드 (매개변수와 이름 겹칠 때 구분용)
    └─ default는 아무것도 안 쓰는 것 자체가 default
