# TIL 09. 제약 조건 (CONSTRAINTS)

> 테이블에 **잘못된 데이터가 들어오지 못하게** 막는 규칙

## 한눈에 보기

| 제약 조건 | 한 줄 설명 | NULL | 중복 |
|---|---|:---:|:---:|
| `NOT NULL` | 빈 값 금지 | ❌ | ⭕ |
| `UNIQUE` | 중복 금지 | ⭕ | ❌ |
| `PRIMARY KEY` | 행을 구분하는 대표 키 (테이블당 1개) | ❌ | ❌ |
| `FOREIGN KEY` | 부모 테이블에 있는 값만 허용 | ⭕ | ⭕ |
| `CHECK` | 직접 정한 조건만 허용 | - | - |
| `DEFAULT` | 값을 안 주면 기본값 | - | - |

> 💡 `PRIMARY KEY` = `NOT NULL` + `UNIQUE`

---

## 1. NOT NULL

**빈 값(NULL)을 넣을 수 없다.**

```sql
CREATE TABLE user_notnull (
    user_no  INT          NOT NULL,
    user_id  VARCHAR(255) NOT NULL,
    user_pwd VARCHAR(255) NOT NULL,
    gender   VARCHAR(3)               -- 제약 없음
);
```

| INSERT 값 | 결과 | 이유 |
|---|:---:|---|
| `(1, 'user01', 'pass01', '남')` | ✅ | |
| `(2, 'user02', NULL, '여')` | ❌ | pwd는 NOT NULL |
| `(3, 'user03', 'pass03', NULL)` | ✅ | gender는 NULL 허용 |

---

## 2. UNIQUE

**같은 값을 두 번 넣을 수 없다.** (NULL은 허용)

```sql
CREATE TABLE user_unique (
    user_no  INT,
    user_id  VARCHAR(255),
    user_pwd VARCHAR(255) NOT NULL,
    gender   VARCHAR(3),
    UNIQUE (user_id)                  -- 테이블 레벨로 지정
);
```

| INSERT 값 | 결과 | 이유 |
|---|:---:|---|
| `(1, 'user01', 'pass01', '남')` | ✅ | |
| `(1, 'user02', 'pass02', '여')` | ✅ | user_no에는 제약 없음 |
| `(3, 'user01', 'pass03', '남')` | ❌ | user_id `user01` 중복 |

---

## 3. PRIMARY KEY

**NULL도 안 되고 중복도 안 된다.** 각 행을 구분하는 대표 값.

```sql
CREATE TABLE user_primarykey (
    user_no  INT PRIMARY KEY,
    user_id  VARCHAR(255),
    user_pwd VARCHAR(255) NOT NULL
);
```

---

## 4. FOREIGN KEY

**자식 테이블에는 부모 테이블에 있는 값만 들어갈 수 있다.**

```sql
-- 부모
CREATE TABLE user_grade (
    grade_code INT PRIMARY KEY,
    grade_name VARCHAR(255) NOT NULL
);
INSERT INTO user_grade VALUES (10, '일반회원'), (20, '우수회원'), (30, '특별회원');

-- 자식
CREATE TABLE user_foreignkey1 (
    user_no    INT PRIMARY KEY,
    grade_code INT,
    FOREIGN KEY (grade_code) REFERENCES user_grade (grade_code)
);
```

| INSERT 값 | 결과 | 이유 |
|---|:---:|---|
| `(1, 10)` | ✅ | 부모에 10 있음 |
| `(2, 99)` | ❌ | 부모에 99 없음 |

### 부모가 바뀌거나 지워지면? (ON UPDATE / ON DELETE)

| 옵션 | 자식은 어떻게 되나 |
|---|---|
| 없음 (기본) | 자식이 참조 중이면 부모 수정·삭제가 **막힘** |
| `SET NULL` | 자식 값이 **NULL**로 바뀜 |
| `CASCADE` | 자식도 **같이 수정·삭제**됨 |

```sql
CREATE TABLE user_foreignkey2 (
    user_no    INT PRIMARY KEY,
    grade_code INT,
    FOREIGN KEY (grade_code) REFERENCES user_grade (grade_code)
        ON UPDATE SET NULL
        ON DELETE SET NULL
);

UPDATE user_grade SET grade_code = 40 WHERE grade_code = 10;
```

→ `user_foreignkey2`에서 `grade_code = 10`이던 행이 **NULL**로 바뀐다.

> ⚠️ 옵션 없는 `user_foreignkey1`이 10을 참조하고 있으면 위 UPDATE는 **막힌다.**

## 5. CHECK

**직접 정한 조건을 만족하는 값만 넣을 수 있다.**

```sql
CREATE TABLE user_check (
    user_no   INT AUTO_INCREMENT PRIMARY KEY,
    user_name VARCHAR(255) NOT NULL,
    gender    VARCHAR(3) CHECK (gender IN ('남', '여')),
    age       INT        CHECK (age >= 19)
);
```

| INSERT 값 | 결과 | 이유 |
|---|:---:|---|
| `(NULL, '홍길동', '남', 25)` | ✅ | |
| `(NULL, '김철수', '남', 15)` | ❌ | 19세 미만 |

---

## 6. DEFAULT

**값을 안 주면 미리 정한 기본값이 들어간다.**

```sql
CREATE TABLE tbl_country (
    country_code INT AUTO_INCREMENT PRIMARY KEY,
    country_name VARCHAR(255) DEFAULT '한국',
    add_day      DATE         DEFAULT (CURRENT_DATE),
    add_time     TIME         DEFAULT (CURRENT_TIME)
);

INSERT INTO tbl_country VALUES (NULL, DEFAULT, DEFAULT, DEFAULT);
```

| country_code | country_name | add_day | add_time |
|---|---|---|---|
| 1 | 한국 | 오늘 날짜 | 현재 시간 |
