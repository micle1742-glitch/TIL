## 1. useMemo — 계산 결과 메모이제이션

### 핵심 개념
- `useMemo`는 렌더링 사이에 **계산 결과값**을 기억한다.
- 의존성 배열의 값이 바뀌면 계산 함수를 다시 실행한다.
- 의존성이 같으면 이전 계산 결과를 재사용할 수 있다.
- 계산 비용이 작다면 굳이 적용할 필요가 없다. 메모이제이션 자체에도 비용이 있다.

### 기본 형태
```jsx
const result = useMemo(() => calculate(value), [value]);
```

### 실습 파일
- `03_hooks/02_usememo/01_usememo-value.html`
- `03_hooks/02_usememo/02_usememo.reference.html`

### 학습 포인트
1. 일반 계산은 컴포넌트가 렌더링될 때 다시 실행될 수 있다.
2. `useMemo`는 지정한 의존성이 바뀌었는지를 기준으로 계산 결과를 재사용한다.
3. 객체·배열은 내용이 같아 보여도 새로 생성되면 참조가 달라질 수 있다.
4. 따라서 의존성에 객체를 넣는 경우, 객체가 매 렌더마다 새로 만들어지는지 확인해야 한다.

### 기억할 문장
`useMemo`는 **함수가 아니라 계산된 값**을 기억한다.

## 2. useCallback — 함수 참조 메모이제이션

### 핵심 개념
- `useCallback`은 함수의 **참조(reference)** 를 기억한다.
- 의존성이 바뀌지 않으면 이전 함수 참조를 재사용한다.
- 자식 컴포넌트에 함수를 props로 전달하거나, 함수 참조를 의존성으로 사용하는 effect가 있을 때 의미가 생길 수 있다.

### 기본 형태
```jsx
const handleAction = useCallback(() => {
  // action
}, [dependency]);
```

### 실습 파일
- `03_hooks/03_useCallback/01_function-memorization.html`
- `03_hooks/03_useCallback/02_conposited-component.html`

### 통합 실습: 상품 검색과 함수 참조
제공된 연습 코드의 구성:
- `inputText`: 입력창에 입력 중인 검색어
- `query`: 검색 버튼을 눌러 실제 적용한 검색어
- `clickCount`: 검색과 관계없는 횟수 상태
- `searchProducts`: 검색어를 `query`에 반영하는 함수
- `filteredProducts`: `PRODUCTS`에서 검색어에 맞는 상품을 필터링한 결과
- `SearchNotice`: `onSearch` 함수 참조를 `[onSearch]` 의존성으로 관찰하는 자식

실습 요구사항:
1. `searchProducts`를 `useCallback`으로 감싼다.
2. 검색과 관계없는 `clickCount`가 바뀌어도 함수 참조가 유지되도록 의존성을 정한다.
3. `filteredProducts`는 `useMemo`로 계산한다.
4. 검색어의 앞뒤 공백과 대소문자를 무시한다.
5. 검색 버튼을 눌렀을 때만 입력값이 실제 검색어로 적용되게 한다.
6. Console에서 상품 목록 재계산 로그와 `SearchNotice` effect 로그를 관찰한다.

### 기억할 문장
`useCallback`은 **함수 참조**를 기억하고, `useMemo`는 **계산 결과값**을 기억한다.

## 3. useRef — 리렌더링을 발생시키지 않는 값 / DOM 참조

### 핵심 개념
- `useRef`로 만든 객체는 렌더링 사이에도 유지된다.
- `ref.current`를 변경해도 그 자체로 리렌더링을 발생시키지 않는다.
- DOM 요소에 접근하거나, 화면 갱신이 필요 없는 값을 유지할 때 사용한다.

### 실습 파일
- `03_hooks/04_useRef/01_rendering-problem.html`
- `03_hooks/04_useRef/02_input-ref.html`

### 두 가지 활용
**1) 값 보관**
- 값은 바뀌지만 그 변화 자체가 UI를 다시 그릴 필요는 없는 경우

**2) DOM 접근**
- input 요소에 포커스 주기
- DOM 요소의 메서드 호출하기

### state와 비교
| 구분 | `useState` | `useRef` |
|---|---|---|
| 값 변경 | setter 사용 | `ref.current` 변경 |
| 변경 시 리렌더링 | 발생 | 발생하지 않음 |
| 대표 용도 | UI에 반영되는 상태 | DOM 접근, 렌더링과 무관한 값 |

## 4. Custom Hook — useDelayReady

### 실습 파일
- `03_hooks/05_custom_hook/01_custom-hook.html`

연습 파일의 요구사항은 `useDelayReady(delay)`를 직접 완성하는 것이다.

### 목표 동작
1. `isReady`를 초기값 `false`로 만든다.
2. `delay` 시간이 지나면 `isReady`를 `true`로 바꾼다.
3. `delay`가 변경되면 다시 대기 상태로 돌아간다.
4. 이전 타이머를 cleanup에서 정리한다.
5. `isReady`를 반환한다.

### 관련 개념
- **Custom Hook**: 여러 컴포넌트에서 재사용할 수 있도록 Hook 로직을 함수로 분리하는 방식
- `useEffect`: 타이머처럼 렌더링 외부의 작업을 처리
- cleanup: 이전 타이머가 남아 중복 실행되지 않도록 정리
- 의존성 `[delay]`: 지연 시간이 바뀔 때 effect를 다시 실행
- `useRef`: 실습 컴포넌트에서 input DOM을 참조
- 첫 렌더링 이후 input에 포커스를 주는 작업은 `useEffect`와 ref를 함께 활용

### 화면에서 확인할 것
- 기본 지연 시간은 2초
- 1초 / 3초 버튼으로 지연 시간을 변경
- 시간이 바뀌면 다시 `기다리는 중`으로 돌아가는지 확인
- 처음 화면이 나타났을 때 이름 input에 포커스가 가는지 확인

## 5. Callback Hell — 콜백 지옥

### 실습 파일
- `04_async/01_intro/01_callback-hell.html`

### 핵심 개념
비동기 작업의 결과를 다음 콜백에서 처리하고, 그 안에 또 콜백을 중첩하면서 코드가 깊어지는 현상이다.

### 문제점
- 실행 흐름을 한눈에 파악하기 어렵다.
- 코드가 깊어지고 가독성과 유지보수성이 떨어진다.

Promise 체이닝이나 `async/await`는 비동기 흐름을 더 읽기 쉽게 구성하는 데 도움이 된다.

## 6. Promise — 비동기 작업의 성공과 실패

### 실습 파일
- `04_async/01_intro/02_promise.html`
- `04_async/01_intro/hooks_promise.practice.html`

### Promise의 기본 상태
- `pending`: 처리 중
- `fulfilled`: 성공
- `rejected`: 실패

### 주요 메서드
- `.then()`: 성공 결과 처리 및 다음 작업 연결
- `.catch()`: 실패 처리
- `.finally()`: 성공·실패와 관계없이 마지막에 실행할 작업

### 실습: 1초마다 10씩 더하기
연습 문제의 요구사항:
1. `addAfterOneSecond(number)`가 Promise를 반환한다.
2. `setTimeout`으로 1초 뒤 `number + 10`을 계산한다.
3. 결과가 30을 초과하면 `reject(new Error(...))`로 실패 처리한다.
4. 그렇지 않으면 결과를 `resolve()`한다.
5. `.then()`을 연결해 10, 20, 30을 순서대로 출력한다.
6. 다음 Promise를 연결할 때 반환값을 `return`한다.
7. 30 이후 한 번 더 실행해 실패 흐름을 확인한다.
8. `.catch()`에서 `error.message`를 출력한다.
9. `.finally()`에서 종료 메시지를 출력한다.

### 중요한 포인트
`.then()` 안에서 다음 Promise를 `return`해야 체인이 그 Promise의 완료를 기다리며 순서대로 이어진다.

## 8. Fetch API — 서버에서 데이터 가져오기

### 실습 파일
- `04_async/02_api/01_fetch.html`
- `04_async/02_api/02_then_async-await.html`

### 기본 흐름
1. `fetch(url)`로 요청을 보낸다.
2. 응답(Response)을 받는다.
3. `response.json()`으로 응답 본문을 JavaScript 데이터로 변환한다.
4. 변환된 데이터를 사용한다.

### 주의할 점
- `fetch()`의 결과는 Promise다.
- `response.json()`도 Promise를 반환하므로 `await`하거나 `return`한 뒤 다음 단계에서 사용한다.
- Fetch는 HTTP 오류 상태(예: 404, 500)만으로 자동 reject되지 않으므로 `response.ok`를 확인하고 필요하면 오류를 발생시킨다.
- 네트워크 오류 등은 `catch`에서 처리한다.

### `.then()` 흐름
`fetch` → 응답 확인 → `response.json()` 반환 → 파싱된 데이터 처리 → `catch`

### `async/await` 흐름
`await fetch()` → `response.ok` 확인 → `await response.json()` → 데이터 처리 (`try/catch`)

## 9. Axios

### 실습 파일
- `04_async/02_api/03_axios.html`

### 핵심 개념
- Axios는 HTTP 요청을 위한 외부 JavaScript 라이브러리다.
- 브라우저에 기본 내장된 Fetch와 달리 별도로 불러와 사용한다.
- `axios.get()` 등 HTTP 메서드를 직관적으로 사용할 수 있다.
- 응답 데이터는 `response.data`에서 확인한다.
- 일반적으로 4xx/5xx HTTP 응답은 Axios가 reject 처리하므로 `catch`에서 다룰 수 있다.

### Fetch와 Axios 비교
| 항목 | Fetch | Axios |
|---|---|---|
| 제공 방식 | 브라우저 기본 API | 외부 라이브러리 |
| JSON 처리 | `response.json()` 필요 | `response.data`로 접근 |
| HTTP 오류 상태 | `response.ok` 확인 필요 | 보통 reject되어 catch로 이동 |

## 11. GitHub Emoji API 검색기 실습

### 실습 파일
- `04_async/02_api/04_github-api-imoji.html`

API:
`https://api.github.com/emojis`

### 컴포넌트 역할 분리
**`App` (부모)**
- 전체 이모지 목록 상태
- 로딩 상태
- 검색 결과 이미지 URL 상태
- API 통신 및 상태 업데이트 담당

**`SearchBox` (자식)**
- 사용자 입력을 받는다.
- 검색 이벤트가 발생하면 검색어를 부모에게 전달한다.
- 어떤 데이터를 검색하는지 직접 관리하지 않고, 부모가 전달한 함수를 호출하는 역할

**`ImageBox` (자식)**
- 부모가 전달한 `loading`, `imgUrl` 등의 상태를 바탕으로 화면을 표시한다.
- API 요청이나 검색 데이터 관리를 직접 하지 않는다.

### 구현 순서 힌트
1. `App`에서 `useEffect`로 처음 렌더링될 때 이모지 목록을 요청한다.
2. Axios 응답에서 이모지 데이터를 꺼내 `emojis` 상태에 저장한다.
3. `SearchBox`에 입력값 state와 검색 이벤트를 만든다.
4. 검색어를 부모의 함수로 전달하도록 props를 연결한다.
5. 부모는 검색어에 해당하는 URL을 찾아 `imgUrl` 상태를 갱신한다.
6. `ImageBox`는 전달받은 상태에 따라 로딩/결과/결과 없음 UI를 표현한다.

※ 제공된 HTML은 컴포넌트의 기본 골격과 상태 선언이 있는 미완성 실습이다. 위 순서는 파일 주석에 적힌 역할과 상태 설계를 정리한 것이며, TODO의 완성 코드를 임의로 채워 넣은 것은 아니다.

## 15. 빠른 최종 복습

- `useMemo` = 값 / `useCallback` = 함수 참조
- `useRef` 변경은 그 자체로 렌더링을 발생시키지 않는다.
- Custom Hook은 재사용 가능한 Hook 로직을 분리한다.
- 타이머 effect는 의존성 변경 시 이전 타이머 cleanup이 중요하다.
- Promise는 `then/catch/finally`, `async/await`는 `try/catch`와 함께 기억한다.
- Fetch는 JSON 파싱과 HTTP 응답 상태 확인을 직접 처리한다.
- Axios는 `response.data`로 응답 데이터에 접근한다.
- API 화면은 `loading → error → data` 상태를 구분해 렌더링한다.
- 부모는 데이터와 상태를 관리하고, 자식은 props로 받은 값과 함수를 활용한다.
