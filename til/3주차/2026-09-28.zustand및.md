# 오늘 배운 내용 나만의 정리

> 학습 순서: **Props Drilling → Basic → Zustand → React Query**

---

# 1. Props Drilling

## 핵심

Props Drilling은 부모의 데이터를 여러 단계의 자식 컴포넌트를 거쳐 전달하는 방식이다.

예시 구조:

    Page → Parent → Child → GrandChild

`Page`에서 만든 `count`와 `setCount`를 `GrandChild`에서 사용하려면 props로 전달할 수 있다.

## 핵심 코드

    const [count, setCount] = useState(0);

    <GrandChild count={count} setCount={setCount} />

자식에서는:

    export default function GrandChild({ count, setCount }) {
      return (
        <>
          <h2>{count}</h2>
          <button onClick={() => setCount(count + 1)}>+1</button>
        </>
      )
    }

## 기억할 것

- `props`는 부모 → 자식으로 데이터를 전달한다.
- 상태 값뿐 아니라 `setState` 함수도 props로 전달할 수 있다.
- 컴포넌트 단계가 깊어지면 props 전달이 복잡해진다.
- 이런 문제를 줄이기 위한 방법 중 하나가 Zustand 같은 전역 상태 관리이다.

# 2. Basic - API와 CRUD

## API 기본 구조

API 호출 코드를 별도 파일로 분리해서 관리할 수 있다.

    const BASE_URL = "http://localhost:4000/posts";

## GET

서버에서 데이터를 가져온다.

    const response = await fetch(BASE_URL);

    if (!response.ok) {
      throw new Error("게시글 목록을 가져오지 못했다");
    }

    return response.json();

`response.json()`은 서버의 JSON 응답을 JavaScript 데이터로 변환한다.

## POST

새 데이터를 서버에 등록한다.

    await fetch(BASE_URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(newPost)
    });

`JSON.stringify()`는 JavaScript 객체를 JSON 문자열로 변환해서 요청 본문으로 보낼 때 사용한다.

## PATCH

기존 데이터의 일부를 수정한다.

    await fetch(`${BASE_URL}/${id}`, {
      method: "PATCH",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ title: updatedTitle })
    });

## DELETE

데이터를 삭제한다.

    await fetch(`${BASE_URL}/${id}`, {
      method: "DELETE"
    });

## CRUD 암기

- Create → `POST`
- Read → `GET`
- Update → `PATCH`
- Delete → `DELETE`

# 3. React에서 CRUD 관리

## 상태

    const [posts, setPosts] = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

- `posts` → 게시글 목록
- `loading` → 로딩 상태
- `error` → 오류 상태

## 데이터 불러오기

    const loadPosts = async () => {
      try {
        setLoading(true);
        setError(null);

        const data = await postApi.getPosts();
        setPosts(data);
      } catch (error) {
        setError(error.message);
      } finally {
        setLoading(false);
      }
    };

핵심 흐름:

`API 요청 → 성공하면 state 저장 → 실패하면 error 저장 → finally에서 loading 종료`

## 처음 실행

    useEffect(() => {
      loadPosts();
    }, []);

의존성 배열이 `[]`이면 처음 렌더링될 때 데이터를 가져오는 용도로 사용할 수 있다.

## 목록 출력

    {posts.map((post) => (
      <div key={post.id}>
        <h3>{post.title}</h3>
        <p>{post.author}</p>
      </div>
    ))}

`map()`으로 배열을 반복 출력하고 `key`로 각 항목을 구분한다.

# 4. Zustand

## Zustand란?

React에서 전역 상태를 관리하기 위한 라이브러리이다.

Props Drilling처럼 상태를 여러 컴포넌트에 계속 전달하지 않고 필요한 컴포넌트에서 Store를 직접 사용할 수 있다.

## Store 기본 형태

    import { create } from "zustand";

    export const useStore = create((set) => ({
      count: 0,

      increase: () =>
        set((state) => ({
          count: state.count + 1
        }))
    }));

## `create`

Zustand Store를 만든다.

## `set`

Store의 상태를 변경한다.

    set({ text: value })

현재 상태를 기준으로 변경할 때:

    set((state) => ({
      count: state.count + 1
    }))

## Store 사용

    const { count, increase } = useStore();

중요한 점은 `useStore()`처럼 호출해서 Store의 상태와 함수를 가져오는 것이다.

---

# 5. Zustand Store 나누기

오늘은 상태의 목적에 따라 Store를 나누는 방식도 사용했다.

- `useUserStore` → 사용자 상태
- `useCartStore` → 장바구니 상태
- `useUIStore` → 모달, 사이드바 등 UI 상태
- `usePersistStore` → 저장이 필요한 상태

---

# 6. User Store + 비동기

Zustand의 Store 안에서도 `async/await`를 이용해서 API 통신을 할 수 있다.

## 핵심 구조

    export const useUserStore = create((set) => ({
      user: null,
      loading: false,

      fetchUser: async () => {
        set({ loading: true });

        try {
          const response = await fetch("API 주소");
          const data = await response.json();
          set({ user: data });
        } finally {
          set({ loading: false });
        }
      }
    }));

## 흐름

`loading true → API 요청 → user 저장 → loading false`

컴포넌트에서는:

    const { user, loading, fetchUser } = useUserStore();

    useEffect(() => {
      fetchUser();
    }, [fetchUser]);

# 7. Cart Store

장바구니처럼 배열 상태도 Zustand로 관리할 수 있다.

## 상품 추가

    addItem: (item) =>
      set((state) => ({
        items: [...state.items, item]
      }))

기존 배열을 복사한 뒤 새로운 `item`을 추가한다.

## 상품 삭제

    removeItem: (id) =>
      set((state) => ({
        items: state.items.filter(
          (item) => item.id !== id
        )
      }))

`filter()`를 이용해서 삭제할 id가 아닌 상품만 남긴다.

## 장바구니 비우기

    clearCart: () =>
      set({ items: [] })

# 8. UI Store

UI 상태도 Zustand로 관리할 수 있다.

    isModalOpen: false,
    isSidebarOpen: false,

    openModal: () =>
      set({ isModalOpen: true }),

    closeModal: () =>
      set({ isModalOpen: false }),

    toggleSidebar: () =>
      set((state) => ({
        isSidebarOpen: !state.isSidebarOpen
      }))

`!state.isSidebarOpen`은 현재 값의 반대로 변경한다.

`true → false`

`false → true`

# 9. Zustand Persist

## persist란?

Zustand의 상태를 `localStorage` 등에 저장해서 새로고침 후에도 상태를 유지할 수 있게 해주는 middleware이다.

## 핵심 구조

    import { persist } from "zustand/middleware";

    export const usePersistStore = create(
      persist(
        (set) => ({
          theme: "light",

          toggleTheme: () =>
            set((state) => ({
              theme:
                state.theme === "light"
                  ? "dark"
                  : "light"
            }))
        }),
        { name: "theme-storage" }
      )
    );

`name`은 localStorage에 저장할 때 사용할 키 이름이다.

## 기억할 것

`Zustand 상태 → persist → localStorage → 새로고침 후에도 유지`

# 10. Hydration

Next.js에서는 서버에서 처음 렌더링한 결과와 브라우저에서 처음 렌더링한 결과가 다르면 Hydration 문제가 발생할 수 있다.

Persist처럼 브라우저의 `localStorage`와 관련된 상태에서 문제가 생길 수 있다.

## 해결 방식

    const [isMounted, setIsMounted] = useState(false);

    useEffect(() => {
      setIsMounted(true);
    }, []);

    if (!isMounted) {
      return <div>로딩중...</div>;
    }

흐름:

`처음 렌더링 → isMounted false → 로딩 표시 → useEffect → true → 실제 화면`

---

# 11. React Query

## React Query란?

서버에서 가져오는 데이터를 관리하기 위한 라이브러리이다.

오늘은 `useQuery`를 이용해서 사용자 목록을 가져왔다.

주요 역할:

- 서버 데이터 조회
- 로딩 상태 관리
- 에러 상태 관리
- 캐시 관리
- 재요청

---

# 12. QueryClient

React Query를 사용하기 위해 `QueryClient`와 `QueryClientProvider`를 사용한다.

## 핵심 구조

    const [queryClient] = useState(
      () => new QueryClient()
    );

    <QueryClientProvider client={queryClient}>
      {children}
    </QueryClientProvider>

`QueryClient`는 query 데이터와 캐시를 관리하는 객체이다.

`QueryClientProvider`는 `queryClient`를 하위 컴포넌트에 공급한다.

---

# 13. useQuery

## 핵심 코드

    const {
      data,
      isLoading,
      isError,
      error,
      refetch,
      isFetching
    } = useQuery({
      queryKey: ["users"],
      queryFn: fetchUsers
    });

## `queryKey`

    queryKey: ["users"]

React Query에서 어떤 Query인지 구분하기 위한 키이다.

예를 들어:

    queryKey: ["users", 1]

처럼 더 구체적으로 구분할 수도 있다.

## `queryFn`

    queryFn: fetchUsers

실제로 서버 데이터를 가져오는 함수이다.

정리하면:

- `queryKey` → 어떤 데이터를 관리할지 식별
- `queryFn` → 그 데이터를 어떻게 가져올지 결정

---

# 14. useQuery 상태

처음 요청할 때는 데이터가 아직 없을 수 있다.

대표적으로:

- `isLoading: true`
- `isFetching: true`
- `data: undefined`

요청 성공 후에는 `data`에 서버 데이터가 들어온다.

요청 실패 시에는 `isError`가 true가 되고 `error`에 오류 정보가 들어온다.

---

# 15. React Query 로딩 / 에러 처리

## 로딩

    if (isLoading) {
      return <h1>데이터를 불러오는중...</h1>;
    }

## 에러

    if (isError) {
      return (
        <>
          <h1>사용자 정보를 가져오지 못함</h1>
          <p>{error.message}</p>
          <button onClick={() => refetch()}>
            다시 시도
          </button>
        </>
      );
    }

## 다시 요청

    refetch()

`refetch()`를 실행하면 해당 Query를 다시 요청한다.

---

# 16. isFetching

    {isFetching && (
      <p>최신 데이터 확인중 ...</p>
    )}

`isFetching`은 현재 fetch 작업이 진행 중인지 확인할 때 사용한다.

`isLoading`은 처음 데이터를 불러오는 로딩을 처리할 때 주로 사용하고, `isFetching`은 재요청까지 포함해 현재 fetch 중인지 확인할 때 사용할 수 있다.

---

# 17. 사용자 목록 출력

    {data.map((user) => (
      <div key={user.id}>
        <strong>{user.name}</strong>
        <p>{user.email}</p>
      </div>
    ))}

React Query로 가져온 `data`도 배열이면 `map()`으로 화면에 출력할 수 있다.

# 18. Zustand와 React Query 차이

## Zustand

주로 애플리케이션 내부에서 사용하는 상태를 관리한다.

예:

- 사용자 상태
- 장바구니
- 모달
- 사이드바
- 테마

흐름:

`컴포넌트 → Zustand Store → 상태`

## React Query

서버에서 가져오는 데이터를 관리하는 데 초점을 둔다.

예:

- 사용자 목록
- 게시글
- 상품 목록
- 서버 데이터
- 로딩
- 에러
- 캐시
- 재요청

흐름:

`컴포넌트 → React Query → API → 서버 데이터`

# 19. 오늘 전체 흐름

`Props Drilling`

→ 부모의 상태를 props로 자식에게 전달

↓

`API / CRUD`

→ 서버와 GET, POST, PATCH, DELETE로 통신

↓

`Zustand`

→ 여러 컴포넌트에서 사용하는 상태를 Store로 관리

↓

`Zustand Persist`

→ 필요한 상태를 localStorage 등에 저장

↓

`React Query`

→ 서버 데이터를 조회하고 로딩, 에러, 캐시, 재요청 등을 관리

# TanStack Query

## 핵심 개념

오늘은 **TanStack Query를 사용해서 서버 데이터를 관리하는 방법**을 배웠다.

### 1. QueryClient

TanStack Query에서 Query와 캐시 등의 데이터를 관리하는 중심 객체이다.

핵심 구조:

`QueryClient`

↓

`QueryClientProvider`

↓

`useQuery`

---

### 2. QueryClientProvider

`QueryClient`를 하위 컴포넌트에서 사용할 수 있도록 제공한다.

즉, `useQuery`를 사용하기 전에 Provider 설정이 필요하다.

핵심 구조:

`QueryClient 생성`

→ `QueryClientProvider에 전달`

→ `하위 컴포넌트에서 useQuery 사용`

---

### 3. useQuery

서버에서 데이터를 가져오고 관리할 때 사용하는 Hook이다.

핵심 구조:

`useQuery`

→ `queryKey`

→ `queryFn`

→ `API 요청`

→ `서버 데이터`

---

### 4. queryKey

Query를 구분하기 위한 키이다.

`["users"]`

특정 데이터를 더 구체적으로 구분할 수도 있다.

`["users", 1]`

- `["users"]` → 사용자 목록
- `["users", 1]` → 1번 사용자

---

### 5. queryFn

실제로 서버에서 데이터를 가져오는 함수이다.

`queryKey` → 어떤 데이터를 구분할지

`queryFn` → 데이터를 어떻게 가져올지

---

### 6. 주요 상태

- `isLoading` → 처음 데이터를 불러오는 중인지 확인
- `isError` → 에러가 발생했는지 확인
- `error` → 발생한 에러 정보
- `isFetching` → 현재 데이터를 가져오는 중인지 확인
- `refetch` → 데이터를 다시 요청
- `data` → 서버에서 받아온 데이터

---

## 자주 헷갈리는 부분

`QueryClient`와 `QueryClientProvider`는 `useQuery` 자체가 아니다.

`QueryClient` → Query를 관리하는 객체

`QueryClientProvider` → QueryClient를 하위 컴포넌트에 제공

`useQuery` → 실제 컴포넌트에서 서버 데이터를 조회하고 관리

---


# 20. 오늘 복습할 핵심만 다시

- Props는 부모 → 자식으로 데이터를 전달한다.
- Props Drilling은 props가 여러 컴포넌트를 거쳐 전달되는 구조이다.
- Zustand의 `create()`로 Store를 만든다.
- Zustand의 `set()`으로 상태를 변경한다.
- `state`를 사용하면 현재 상태를 기준으로 값을 변경할 수 있다.
- `persist`를 사용하면 Zustand 상태를 저장할 수 있다.
- Hydration은 서버 렌더링과 브라우저의 초기 렌더링 차이와 관련된다.
- CRUD는 `POST / GET / PATCH / DELETE`로 연결해서 기억한다.
- `JSON.stringify()`는 JavaScript 객체를 JSON 문자열로 만든다.
- `response.json()`은 JSON 응답을 JavaScript 데이터로 변환한다.
- React Query의 `queryKey`는 Query를 식별한다.
- React Query의 `queryFn`은 실제 데이터를 가져오는 함수이다.
- `isLoading`은 처음 데이터를 불러오는 로딩 처리에 사용한다.
- `isError`와 `error`로 오류를 처리한다.
- `refetch()`로 Query를 다시 요청한다.
- `isFetching`으로 현재 fetch 진행 여부를 확인할 수 있다.
`TanStack Query`
→ `QueryClient 생성`
→ `QueryClientProvider 설정`
→ `useQuery 사용`
→ `queryKey + queryFn`
→ `API 요청`
→ `data / loading / error / fetching / refetch`로 서버 데이터 관리
## 한 줄 정리


**Props Drilling으로 데이터 전달 방식을 이해하고, API CRUD로 서버 통신을 배우고, Zustand로 전역 상태를 관리하고, Persist로 상태를 저장하고, React Query로 서버 데이터를 관리하는 흐름을 배웠다.**
**오늘은 TanStack Query의 Provider를 설정하고 `useQuery`를 이용해 서버 데이터를 관리하는 방법까지 배웠다.**
