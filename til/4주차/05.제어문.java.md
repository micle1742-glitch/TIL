# Java 복습 - chap04 제어문 (Control Flow)

## 학습 순서
1. 조건문 - if / if-else / if-else if / switch / 향상된 switch
2. 반복문 - for / 중첩 for / while / do-while
3. 분기문 - break / continue / return / 라벨 / flag

> 제어문: 코드는 원래 위에서 아래로 한 줄씩 실행되는데, 이 흐름을 **조건에 따라 고르거나(조건문), 반복하거나(반복문), 중간에 끊는(분기문)** 문법

---

## 1. 조건문

### 1-1. if (조건이 true일 때만 실행)

    if (num % 2 == 0) {
        System.out.println("짝수입니다.");
    }
    System.out.println("프로그램을 종료합니다."); // if와 상관없이 항상 실행

- 조건식 결과는 반드시 **boolean** (true/false)
- JS처럼 `if (num)` 같은 숫자 조건 **불가** → 자바는 `if (num != 0)`처럼 써야 함

### 1-2. if-else (둘 중 하나는 무조건 실행)

    if (num % 2 != 0) {
        System.out.println("홀수");
    } else {
        System.out.println("짝수");   // 조건이 false일 때
    }

### 1-3. if-else if-else (여러 조건 중 처음 맞는 하나만)

    if (point >= 90) {
        grade = "A";
        if (point >= 95) { grade += "+"; }   // 중첩 if
    } else if (point >= 70) {
        grade = "C";
    } else if (point >= 50) {
        grade = "D";
    } else {
        grade = "F";
    }

- **위에서부터 검사하다가 처음 true인 블록 하나만** 실행하고 나머지는 건너뜀
- 그래서 **큰 범위 조건을 아래에, 좁은 조건을 위에** 둬야 함
  - `point >= 50`을 맨 위에 두면 95점도 D가 됨

### 1-4. switch (값이 딱 맞는 case로 이동)

    switch (op) {
        case '+':
            result = first + second;
            break;
        case '-':
            result = first - second;
            break;
        default:                 // 어떤 case에도 안 맞을 때
            System.out.println("잘못된 연산 기호");
            return;              // 메소드 자체 종료
    }

- 범위 비교(>=, <)는 못 하고 **값이 같은지**만 비교 → 범위는 if, 정해진 값 고르기는 switch
- switch에 쓸 수 있는 타입: int 계열(byte, short, int), char, String, enum (long, double, boolean **X**)
- 연산 기호 입력: `char op = sc.next().charAt(0);` (Scanner엔 char 입력이 없어서)

### 1-5. 향상된 switch (Java 14+, 화살표 문법)

    int result2 = switch (op) {
        case '+' -> first + second;
        case '-' -> first - second;
        default -> {
            System.out.println("잘못된 기호입니다.");
            yield 0;     // 중괄호 블록에서 값을 돌려줄 땐 yield
        }
    };                   // 값으로 쓰는 switch라서 세미콜론 필요

### 기존 switch vs 향상된 switch
| | 기존 `case :` | 향상된 `case ->` |
|---|---|---|
| break | 필요 (안 쓰면 아래로 흘러감) | 필요 없음 |
| 결과를 값으로 받기 | X (변수에 따로 대입) | O (`int r = switch(...) {...};`) |
| 블록에서 값 반환 | - | `yield 값;` |
| 끝 | `}` | 값으로 쓸 땐 `};` |

### 헷갈리는 부분
- **break 빼먹으면 fall-through**: 맞는 case부터 break 만날 때까지 아래 case들도 전부 실행됨
- **yield vs return**
  - `yield`: switch의 **결과값만 정하고** switch만 끝남
  - `return`: **메소드 전체**가 끝남
- 향상된 switch를 값으로 쓸 땐 **default 필수** (모든 경우에 값이 있어야 해서)
- [코드 확인] 수업 점수 코드엔 **B(80점대) 조건이 없어서** 85점이면 `point >= 70`에 걸려 "C+"가 나옴 → 직접 `else if (point >= 80) { grade = "B"; ... }` 추가해보기

## 2. 반복문

### 2-1. for (반복 횟수가 정해져 있을 때)

    for (int i = 1; i <= 5; i++) {
        // 초기식; 조건식; 증감식
    }

- 실행 순서 (암기): **초기식 → 조건식 → 본문 → 증감식 → 조건식 → 본문 → ...** → 조건 false면 종료
- 구조는 JS와 같고, 차이는 `let i` 대신 **`int i`처럼 자료형을 씀**
- `i`는 for문 안에서 선언했으니 **for문 밖에선 못 씀**

### 왜 반복문?
- 학생 이름 2명 입력은 코드 복붙으로 되지만 100명이면? → 같은 패턴은 반복문으로, 바뀌는 부분(번호)만 `i`로

### 누적 합계 패턴 (자주 씀)

    int sum = 0;                  // 반복문 밖에서 선언 + 0으로 초기화
    for (int i = 1; i <= num; i++) {
        sum += i;                 // sum = sum + i
    }

- `sum`을 반복문 **안에서** 선언하면 매 회차마다 0으로 초기화돼서 누적 안 됨 + 밖에서 출력도 못 함

### 2-2. 중첩 for (구구단)

    for (int dan = 2; dan <= 9; dan++) {        // 바깥: 단
        for (int su = 1; su <= 9; su++) {       // 안쪽: 곱하는 수
            System.out.println(dan + " * " + su + " = " + dan * su);
        }
    }

- 바깥 1회 돌 때 **안쪽은 처음부터 끝까지 전부** 돔 → 총 8 × 9 = 72번 출력
- 바깥 = 행(큰 단위), 안쪽 = 열(작은 단위)로 생각하면 편함

### 2-3. while (반복 횟수가 정해져 있지 않을 때)

    String str = "";
    while (!str.equals("exit")) {
        str = sc.nextLine();
        System.out.println("입력한 문자열 : " + str);
    }

- 조건을 **먼저 검사** → 처음부터 false면 한 번도 실행 안 됨
- 그래서 `str`을 `""`로 초기화해서 첫 검사를 통과시킨 것
- 조건이 계속 true면 **무한 루프** → 본문 안에서 조건을 바꾸는 코드(`str = ...`, `i++`) 꼭 있어야 함

### 2-4. do-while (최소 1번은 실행)

    String str;
    do {
        str = sc.nextLine();
        System.out.println("입력한 문자열 : " + str);
    } while (!str.equals("exit"));   // 세미콜론 주의!

- **본문 먼저 실행 → 나중에 조건 검사**
- 본문에서 처음 값을 넣으니까 `str`을 미리 초기화 안 해도 됨
- 메뉴 출력, 입력받기처럼 "일단 한 번은 보여줘야 하는" 경우에 씀

### 반복문 선택 기준
| 상황 | 반복문 |
|---|---|
| 횟수가 정해짐 (1~100, 5명) | for |
| 횟수 모름, 조건 만족할 때까지 | while |
| 횟수 모름 + 최소 1번은 실행 | do-while |

### 헷갈리는 부분
- 문자열 비교는 `==` 말고 **`.equals()`** → `==`는 내용이 아니라 같은 객체인지 비교해서 Scanner 입력값이랑 비교하면 false 나올 수 있음
- `do { } while(조건);` 끝에 **세미콜론** 필수 (while문엔 없음)
- `!str.equals("exit")` = "exit가 **아니면** 계속 반복"

## 3. 분기문 (break / continue / return)

### 한눈에 비교 (암기)
| | 끝내는 범위 | 다음 동작 |
|---|---|---|
| `break` | **가장 가까운** 반복문 / switch | 반복문 밖 다음 줄로 |
| `continue` | **이번 회차만** | 증감식 → 조건식 → 다음 회차 |
| `return` | **메소드 전체** | 호출한 곳으로 돌아감 |

### 3-1. break + 무한 루프

    while (true) {
        sum += i;
        if (i == 10) {
            break;     // 조건 만족하면 탈출
        }
        i++;
    }

- `while(true)` + `break` 조합: 종료 조건이 반복문 중간에 있을 때 자주 씀

### 3-2. 중첩 반복문에서 break

    for (int dan = 2; dan <= 9; dan++) {
        for (int su = 1; su <= 9; su++) {
            if (su > 3) break;   // 안쪽 for만 탈출
            ...
        }
    }

- 결과: 모든 단이 `× 1, 2, 3`까지만 출력됨 (바깥 for는 계속 돔)

### 3-3. continue

    for (int i = 1; i <= 100; i++) {
        if (!(i % 4 == 0 && i % 5 == 0)) {
            continue;    // 공배수가 아니면 아래 출력 건너뜀
        }
        System.out.println(i);    // 20, 40, 60, 80, 100
    }

- "조건에 안 맞는 건 걸러내고 다음으로" 할 때 사용
- [코드 확인] 주석엔 "4의 배수이면서 5의 배수가 아니라면"이라고 돼 있는데, 실제 조건 `!(A && B)`는 **"4와 5의 공배수가 아니라면"**이 맞음

### 3-4. 중첩 반복문 전체 탈출 2가지

**방법 1. 라벨**

    outer:
    for (int dan = 2; dan <= 9; dan++) {
        for (int su = 1; su <= 9; su++) {
            if (su > 3) break outer;   // 라벨 붙은 바깥 for까지 탈출
        }
    }

**방법 2. boolean flag**

    boolean isBreak = false;
    for (...) {
        for (...) {
            if (조건) {
                isBreak = true;   // 탈출 신호
                break;            // 안쪽 탈출
            }
        }
        if (isBreak) break;       // 신호 확인 후 바깥 탈출
    }

- 결과: 둘 다 **2단의 1~3까지만 출력**하고 전체 종료
- 라벨은 짧지만 흐름이 튀어서 읽기 어렵고, flag는 길지만 흐름이 명확함 → 실무에선 아예 **메소드로 분리하고 return**하는 방식도 많이 씀

### 헷갈리는 부분
- break는 **if를 탈출하는 게 아님** → if를 감싸고 있는 가장 가까운 반복문/switch를 탈출
- for문에서 continue → 증감식(`i++`)으로 감 / while에서 continue → 바로 조건식으로 감
  - while에서 `i++`이 continue 아래에 있으면 **i가 안 늘어나서 무한 루프** 위험
- 라벨 문법: `이름:`을 **반복문 바로 앞**에 쓰고, `break 이름;`

## 셀프 체크 (OX)
- if-else if에서 조건이 여러 개 true면 전부 실행된다 → X (처음 하나만)
- 기존 switch에서 break가 없으면 다음 case도 실행된다 → O
- 향상된 switch의 중괄호 블록에서 값을 돌려줄 땐 return을 쓴다 → X (yield)
- while은 조건이 처음부터 false면 한 번도 실행 안 된다 → O
- do-while은 조건이 처음부터 false여도 1번은 실행된다 → O
- break는 중첩 반복문 전체를 한 번에 탈출한다 → X (가장 가까운 것만)
- 문자열 비교는 `==`보다 `.equals()`를 쓴다 → O

## 전체 흐름 정리
프로그램은 기본적으로 위에서 아래로 흐르는데, **조건문**으로 갈 길을 고른다 (범위 비교는 if, 정해진 값 고르기는 switch, 값을 바로 받고 싶으면 향상된 switch + yield).
같은 작업을 여러 번 해야 하면 **반복문**을 쓴다 (횟수 정해짐 → for, 모름 → while, 최소 1번 → do-while). 누적 변수는 반복문 밖에 선언.
반복 도중 흐름을 끊고 싶으면 **분기문**: break는 가장 가까운 반복문 탈출, continue는 이번 회차만 건너뛰기, return은 메소드 통째로 종료. 중첩 반복문 전체를 끊을 땐 라벨이나 flag.
chap03에서 배운 메소드 + Scanner와 합치면 "입력 받기 → 조건 판단 → 반복 처리" 하는 작은 프로그램을 만들 수 있다.
