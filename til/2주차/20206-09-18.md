# 오늘 배운 React 정리

## 1. `key` - 리스트의 각 항목을 구분하는 고유한 값

React에서 `map()`으로 여러 항목을 화면에 출력할 때 각 항목을 구분하기 위해 `key`를 사용한다.

예:
`users.map(user => (
    <li key={user.id}>{user.name}</li>
))`

- `key`는 React가 각각의 리스트 항목을 구분하기 위한 값
- 보통 객체가 가지고 있는 고유한 `id`를 사용
- 화면에 실제로 표시되는 값은 아님

# 2. React에서 배열에 데이터 추가하기

오늘은 `useState`로 관리하는 배열에 새로운 데이터를 추가하고 삭제하는 방법을 배웠다.

## 2-1. `useState` 만들기

예:
`const [inputText, setInputText] = useState('');`

`const [todos, setTodos] = useState([
    { id: 1, text: 'React 복습하기' },
    { id: 2, text: 'Todo List 완성하기' }
]);`

`const [nextId, setNextId] = useState(3);`

각 state의 역할:

- `inputText` → input에 현재 입력되어 있는 값
- `setInputText` → `inputText`를 변경하는 함수
- `todos` → 할 일 목록을 저장하는 배열
- `setTodos` → `todos` 상태를 변경하는 함수
- `nextId` → 다음에 추가할 할 일의 ID

---

# 3. `value`와 `onChange`

## `value`

`value={inputText}`

input의 값을 `inputText` state와 연결한다.

즉 React가 input의 값을 state로 관리하게 된다.

`<input value={inputText} />`

---

## `onChange`

사용자가 input에 글자를 입력하면 `onChange`가 실행된다.

예:
`const handleChange = (event) => {
    setInputText(event.target.value);
};`

`<input
    value={inputText}
    onChange={handleChange}
/>`

흐름:

사용자가 글자를 입력
→ `onChange` 실행
→ `event.target`은 이벤트가 발생한 input 요소
→ `event.target.value`는 input에 현재 입력된 문자열
→ `setInputText()`로 state 변경
→ React가 다시 렌더링

### 핵심

`event.target`
→ 이벤트가 발생한 요소 자체

`event.target.value`
→ 그 input에 현재 들어있는 값

따라서 `setInputText(event.target)`가 아니라 `setInputText(event.target.value)`를 사용한다.

# 4. 입력값의 공백 검사 - `trim()`

추가하기 전에 입력값이 공백뿐인지 검사한다.

예:
`if (inputText.trim() === '') {
    return;
}`

`trim()`은 문자열의 앞뒤 공백을 제거한다.

예:

`"  React  ".trim()`
→ `"React"`

`"     ".trim()`
→ `""`

따라서 공백만 입력했을 경우:

`inputText.trim() === ''`
→ `true`
→ `return`
→ 함수 종료
→ 할 일을 추가하지 않음

# 5. 새로운 할 일 객체 만들기

새로운 할 일을 객체로 만든다.

예:
`const newTodo = {
    id: nextId,
    text: inputText
};`

예를 들어:

`nextId = 3`
`inputText = 'React 공부하기'`

라면:

`{
    id: 3,
    text: 'React 공부하기'
}`

라는 새로운 객체가 만들어진다.

# 6. Spread 문법으로 배열에 추가하기

기존 배열을 직접 수정하지 않고 Spread 문법을 사용해 새로운 배열을 만든다.

예:
`setTodos([...todos, newTodo]);`

`...todos`
→ 기존 배열의 요소를 하나씩 펼친다.

예를 들어:

`todos = [
    { id: 1, text: 'React 복습하기' },
    { id: 2, text: 'Todo List 완성하기' }
]`

`newTodo = {
    id: 3,
    text: 'React 공부하기'
}`

`[...todos, newTodo]`

→

`[
    { id: 1, text: 'React 복습하기' },
    { id: 2, text: 'Todo List 완성하기' },
    { id: 3, text: 'React 공부하기' }
]`

즉:

기존 배열 펼치기
→ 새 할 일 추가
→ 새로운 배열 생성
→ `setTodos()`에 전달

### 왜 setter에 전달할까?

`setTodos()`는 `todos` state를 변경하는 함수이다.

따라서:

`setTodos([...todos, newTodo])`

는

"기존 todos를 바탕으로 새로 만든 이 배열을 todos state로 바꿔줘"

라는 뜻이다.

React에서는 기존 state 배열을 직접 수정하기보다 새로운 배열을 만들어 setter에 전달하는 방식으로 상태를 변경한다.

---

# 7. `nextId`를 증가시키는 이유

새로운 할 일이 추가될 때마다 고유한 ID를 사용해야 한다.

예:
`setNextId(nextId + 1);`

처음:

`nextId = 3`

새로운 할 일:

`id: 3`

추가 후:

`nextId = 4`

다음 할 일은:

`id: 4`

이런 식으로 ID가 계속 증가한다.

---

# 8. 추가한 후 input을 비우는 이유

추가가 끝난 후:

`setInputText('');`

를 사용한다.

왜냐하면 input이:

`value={inputText}`

로 state와 연결되어 있기 때문이다.

예:

사용자가 `"React 공부"` 입력
→ `inputText = "React 공부"`
→ 추가 버튼 클릭
→ 할 일 추가
→ `setInputText('')`
→ `inputText = ""`
→ input 화면도 빈칸이 됨

즉 추가가 끝난 뒤 **다음 할 일을 입력할 수 있도록 입력창을 초기화하는 것**이다.

---

# 9. 배열에서 삭제하기 - `filter()`

삭제할 때 사용하는 핵심:

`const updateTodos = todos.filter(todo => todo.id !== idToRemove);
setTodos(updateTodos);`

## `filter()`란?

`배열.filter(callback)`

배열의 각 요소를 하나씩 검사한 뒤 callback이 `true`를 반환한 요소만 모아서 **새로운 배열을 반환**한다.

---

# 10. `filter()`로 특정 항목 삭제하기

예:

`todos = [
    { id: 1, text: '공부' },
    { id: 2, text: '운동' },
    { id: 3, text: '게임' }
]`

삭제할 ID:

`idToRemove = 2`

조건:

`todo.id !== idToRemove`

하나씩 검사하면:

`1 !== 2`
→ `true`
→ 남김

`2 !== 2`
→ `false`
→ 제외

`3 !== 2`
→ `true`
→ 남김

결과:

`[
    { id: 1, text: '공부' },
    { id: 3, text: '게임' }
]`

즉 `filter()`는 실제로 배열에서 뭔가를 지우는 것보다는 **삭제할 요소를 제외하고 새로운 배열을 만드는 것**이다.

---

# 11. `const updateTodos = ...`의 의미

`const updateTodos = todos.filter(...)`

여기서 `filter()`가 만든 새로운 배열을 `updateTodos`라는 변수에 저장한다.

흐름:

`todos`
→ `filter()`
→ 삭제할 항목을 제외한 새로운 배열
→ `updateTodos`에 저장

그 다음:

`setTodos(updateTodos);`

→ `updateTodos`에 들어있는 새로운 배열을 `todos` state에 넣는다.

즉:

`filter()` → 새 배열 만들기

`updateTodos` → 새 배열을 담아두는 변수

`setTodos(updateTodos)` → 그 새 배열을 state에 전달

---

# 12. 왜 `filter()`를 사용하는가?

React에서는 state를 직접 수정하기보다 새로운 값을 만들어 setter로 전달하는 방식을 사용한다.

따라서:

기존 `todos`
→ `filter()`로 새로운 배열 생성
→ `setTodos()`로 새로운 배열 전달
→ state 변경
→ React가 다시 렌더링
→ 삭제된 항목이 화면에서 사라짐

---

# 13. `map()`으로 목록 렌더링

배열의 데이터를 화면에 여러 개 출력할 때 `map()`을 사용한다.

예:
`todos.map(todo => (
    <TodoItem
        key={todo.id}
        todo={todo}
        onRemove={handleRemove}
    />
))`

`map()`은 배열의 각 요소를 하나씩 꺼내서 원하는 형태로 변환한다.

예:

`todos`
→ todo 1
→ TodoItem

→ todo 2
→ TodoItem

→ todo 3
→ TodoItem

이런 식으로 각각의 데이터를 화면에 렌더링한다.

---

# 14. `TodoItem` 자식 컴포넌트

오늘 Todo List에서는 할 일 하나를 화면에 표시하는 역할을 `TodoItem`이라는 자식 컴포넌트가 담당한다.

예:
`function TodoItem({ todo, onRemove }) {
    return (
        <li className="todo-item">
            <span>{todo.text}</span>
            <button onClick={() => onRemove(todo.id)}>
                삭제
            </button>
        </li>
    );
}`

`todo`
→ 하나의 할 일 객체

`onRemove`
→ 부모가 전달해준 삭제 함수

---

# 15. 부모 → 자식으로 props 전달

부모인 `TodoList`에서:

`<TodoItem
    key={todo.id}
    todo={todo}
    onRemove={handleRemove}
/>`

이렇게 전달한다.

각각의 의미:

`key={todo.id}`
→ React가 리스트 항목을 구분하기 위한 고유값

`todo={todo}`
→ 할 일 객체를 자식에게 전달

`onRemove={handleRemove}`
→ 부모의 삭제 함수를 자식에게 전달

---

# 16. 자식 → 부모의 함수 실행

자식 컴포넌트의 삭제 버튼:

`<button onClick={() => onRemove(todo.id)}>
    삭제
</button>`

버튼을 클릭하면:

`onRemove(todo.id)`

가 실행된다.

부모에서:

`onRemove={handleRemove}`

로 전달했기 때문에 결국 부모의:

`handleRemove(todo.id)`

가 실행된다.

흐름:

부모 `TodoList`
→ `handleRemove`를 자식에게 전달
→ 자식 `TodoItem`
→ 삭제 버튼 클릭
→ `onRemove(todo.id)`
→ 부모의 `handleRemove(todo.id)`
→ `filter()`
→ 해당 ID를 제외한 새 배열
→ `setTodos()`
→ 화면 업데이트

---

# 17. 왜 `onClick={() => onRemove(todo.id)}`인가?

`todo.id`를 함수에 전달해야 하기 때문이다.

`onClick={onRemove}`
→ 함수 자체를 전달

`onClick={() => onRemove(todo.id)}`
→ 클릭했을 때 `todo.id`를 넣어서 함수 실행

즉 클릭하기 전에는 실행하지 않고, **클릭했을 때 ID를 전달하면서 실행**하기 위해 화살표 함수를 사용한다.

---

# 18. `useEffect`

`useEffect`는 React에서 제공하는 Hook 함수이다.

`useState`
→ 상태 관리

`useEffect`
→ 렌더링 이후 특정 작업을 실행하거나 정리

`useEffect`는 화면을 그리는 코드가 아니라,
**화면이 그려진 뒤 실행할 부수효과(side effect)를 작성하는 자리**라고 이해하면 된다.

오늘 사용한 예:

- 콘솔 출력
- 타이머 등록
- 현재 시간과 같은 동작
- 이벤트 등록
- API 요청과 같은 작업

---

# 19. `useEffect`의 실행 시점

기본 형태:

`useEffect(() => {
    // 실행할 코드
}, [의존성 배열]);`

## ① 의존성 배열 생략

`useEffect(() => {
    console.log('렌더링 될 때마다 실행');
});`

→ 렌더링될 때마다 실행

---

## ② 빈 의존성 배열 `[]`

`useEffect(() => {
    console.log('컴포넌트가 처음 화면에 나타남');
}, []);`

→ 컴포넌트가 처음 화면에 나타날 때 실행

쉽게 말하면:

`[]`
→ 의존하는 값이 없음
→ 처음 Mount될 때 실행

---

## ③ 특정 값 지정

`useEffect(() => {
    console.log(`count값이 ${count}로 변경`);
}, [count]);`

→ 처음 실행되고 `count`가 변경될 때 다시 실행

예를 들어 `otherCount`만 변경되고 `count`가 변경되지 않았다면 `[count]`를 가진 이 Effect는 다시 실행되지 않는다.

---

# 20. 의존성 배열 한 번에 정리

`useEffect(fn)`
→ 렌더링마다 실행

`useEffect(fn, [])`
→ 처음 한 번 실행

`useEffect(fn, [x])`
→ 처음 실행 + `x`가 변경될 때 실행

---

# 21. Cleanup 함수

`useEffect`에서는 `return`을 이용해 정리 함수를 만들 수 있다.

예:

`useEffect(() => {
    // 작업 시작

    return () => {
        // 작업 정리
    };
}, []);`

이 `return () => {}`는 지금 바로 실행하라는 뜻이 아니라,
**나중에 Effect가 정리되어야 할 때 실행할 함수를 반환하는 것**이다.

---

# 22. 타이머와 Cleanup

오늘 `Timer` 컴포넌트에서:

`const timerId = setInterval(() => {
    console.log('..1초 경과...');
}, 1000);`

를 사용했다.

`setInterval()`
→ 일정 시간마다 반복해서 실행하는 타이머를 만든다.

`const timerId`
→ 만들어진 타이머의 ID를 저장한다.

그리고:

`return () => {
    console.log('타이머를 정리합니다');
    clearInterval(timerId);
}`

에서:

`clearInterval(timerId)`
→ 이전에 만든 타이머를 제거한다.

---

# 23. Cleanup이 필요한 이유

컴포넌트가 화면에서 사라졌는데도 타이머가 계속 실행되면 불필요한 작업이 계속될 수 있다.

그래서:

`setInterval()`
→ 타이머 생성

`clearInterval()`
→ 타이머 제거

를 연결해서 사용한다.

흐름:

`Timer` 컴포넌트 등장
→ `useEffect` 실행
→ `setInterval()`로 타이머 생성
→ 타이머 실행
→ `Timer` 컴포넌트가 화면에서 사라짐
→ Cleanup 실행
→ `clearInterval(timerId)`
→ 타이머 제거

---

# 24. Cleanup은 Unmount 때만 사용하는 것은 아님

Cleanup 함수는 컴포넌트가 화면에서 사라지는 `Unmount` 상황에서 실행된다.

또한 의존성이 있는 Effect라면,
의존성 값이 바뀌어서 Effect가 다시 실행되기 전에 이전 작업을 정리하는 데도 사용한다.

즉:

`Effect`
→ 작업 시작

`Cleanup`
→ 이전 작업 정리

---

# 25. `showTimer` state

오늘 `App`에서는:

`const [showTimer, setShowTimer] = useState(true);`

를 사용했다.

두 개가 나온 이유는 `useState()`가 현재 값과 상태 변경 함수를 함께 반환하기 때문이다.

`showTimer`
→ 현재 상태값

`setShowTimer`
→ 상태를 변경하는 함수

초기값:

`true`

즉 처음에는 타이머를 보여주는 상태이다.

---

# 26. `true / false`로 타이머 보이기/숨기기

버튼:

`<button onClick={() => setShowTimer(!showTimer)}>
    타이머 보이기/숨기기
</button>`

여기서 `!`는 현재 값을 반대로 바꾼다.

`true`
→ `!true`
→ `false`

`false`
→ `!false`
→ `true`

따라서 버튼을 누를 때마다:

`true → false → true → false → ...`

로 상태가 바뀐다.

쉽게 생각하면 `showTimer`를 **켜짐/꺼짐 스위치**로 생각하면 된다.

---

# 27. `showTimer && <Timer />`

`{showTimer && <Timer />}`

는 조건부 렌더링이다.

뜻:

**`showTimer`가 true일 때만 `<Timer />`를 보여준다.**

`showTimer = true`
→ `true && <Timer />`
→ `<Timer />` 표시

`showTimer = false`
→ `false && <Timer />`
→ `<Timer />` 표시하지 않음

---

# 28. `showTimer` 전체 흐름

처음:

`showTimer = true`
→ 타이머 보임

버튼 클릭:

`setShowTimer(!showTimer)`
→ `true`를 `false`로 변경
→ 타이머 사라짐

다시 버튼 클릭:

`setShowTimer(!showTimer)`
→ `false`를 `true`로 변경
→ 타이머 다시 나타남

즉:

`showTimer`
→ 현재 타이머 표시 상태

`setShowTimer`
→ 그 상태를 변경

`!showTimer`
→ 현재 상태를 반대로 변경

`showTimer && <Timer />`
→ true일 때만 Timer 렌더링

---

# 29. `showTimer`와 Cleanup 연결

이 부분이 오늘 배운 내용을 연결하는 중요한 부분이다.

`showTimer = true`
→ `<Timer />` 존재
→ Timer의 `useEffect` 실행
→ 타이머 생성

버튼 클릭
→ `showTimer = false`
→ `<Timer />`가 화면에서 사라짐
→ Timer가 Unmount
→ Cleanup 실행
→ `clearInterval(timerId)`
→ 타이머 정리

즉 `showTimer`로 Timer를 보이게 하고 숨기는 과정에서
`useEffect`의 Cleanup까지 연결된다.

# ⭐ 오늘 배운 핵심 한 번에 정리

`useState`
→ React에서 상태를 관리한다.

`inputText`
→ input에 현재 입력된 값을 저장한다.

`value`
→ input과 state를 연결한다.

`onChange`
→ input 값이 변경될 때 실행된다.

`event.target.value`
→ 현재 input에 입력된 값을 가져온다.

`trim()`
→ 앞뒤 공백을 제거해서 빈 값인지 검사한다.

`Spread (...)`
→ 기존 배열을 펼쳐 새로운 배열을 만든다.

`setTodos(...)`
→ 새 배열을 todos state에 전달한다.

`nextId`
→ 다음에 사용할 고유 ID를 관리한다.

`setInputText('')`
→ 추가가 끝난 후 input을 비운다.

`map()`
→ 배열의 각 요소를 화면에 렌더링한다.

`key`
→ React가 리스트의 각 항목을 구분하기 위한 고유값이다.

`filter()`
→ 조건이 true인 요소만 모아서 새로운 배열을 만든다.

`setTodos(updateTodos)`
→ filter로 만든 새 배열을 state에 넣는다.

`props`
→ 부모가 자식에게 데이터를 전달하는 방법이다.

`TodoItem`
→ 할 일 하나의 화면 표시를 담당하는 자식 컴포넌트이다.

`onRemove`
→ 부모의 삭제 함수를 자식에게 전달한다.

`onRemove(todo.id)`
→ 자식이 삭제할 ID를 부모의 함수에 전달한다.

`useEffect`
→ 렌더링 이후 특정 작업을 실행하거나 정리한다.

`useEffect(fn)`
→ 렌더링마다 실행한다.

`useEffect(fn, [])`
→ 처음 화면에 나타날 때 실행한다.

`useEffect(fn, [x])`
→ 처음 실행 + `x`가 변경될 때 실행한다.

`return () => {}`
→ Cleanup 함수이다.

`setInterval()`
→ 반복 작업을 시작한다.

`clearInterval()`
→ 만들어진 반복 작업을 정리한다.

`showTimer`
→ Timer를 보여줄지 말지 나타내는 현재 상태값이다.

`setShowTimer`
→ `showTimer` 상태를 변경하는 함수이다.

`!showTimer`
→ true와 false를 반대로 바꾼다.

`showTimer && <Timer />`
→ `showTimer`가 true일 때만 Timer를 화면에 보여준다.

# 🧠 오늘 배운 것을 내 방식으로 이해하기

React는 결국:

**state를 만든다**
→ 데이터를 기억한다.

**input과 state를 연결한다**
→ `value`, `onChange`

**state를 변경한다**
→ setter 사용

**배열에 추가한다**
→ Spread + setter

**배열에서 삭제한다**
→ filter + setter

**배열을 화면에 보여준다**
→ map + key

**컴포넌트를 나눈다**
→ 부모 → 자식 props 전달

**렌더링 이후 해야 할 작업이 있다**
→ useEffect

**Effect에서 만든 작업을 정리해야 한다**
→ Cleanup

**컴포넌트를 보여주거나 숨긴다**
→ true / false state + 조건부 렌더링

이렇게 연결해서 이해하면 된다.
